# frontend bug 修复:主题选月亮后刷新变亮色(图标仍月亮)

| 日期   | 2026-07-31                                                                   |
| ------ | ---------------------------------------------------------------------------- |
| 类型   | bug 修复(前端主题持久化)                                                     |
| 现象   | 顶栏点月亮切到暗色,刷新页面后**界面变亮色**,但主题图标**仍是月亮**           |
| 影响面 | 所有用户:手动选择的主题在刷新后不生效(暗色被重置为亮色),图标与实际主题不一致 |

## 1. 现象与根因

点击月亮能正常切暗色(`toggle→applyTheme` 直接操作 `<html>` class + 写 localStorage),
但**刷新后界面变亮、图标却仍是月亮**。这个「state=dark 但 DOM 无 `.dark`」的分裂,是定位关键。

主题链路有两层设 `<html>.dark`:

1. **防 FOUC 内联脚本**(`theme-constants.ts` `buildThemeInlineScript`,由 `layout.tsx` 内联进 HTML,
   SSR 时同步执行):读 `localStorage` + 系统偏好,hydration 前设好 `<html>.dark`。
2. **`ThemeProvider` 的 `useEffect`**:hydration 后把 React state 对齐到实际主题。

`theme` 能变成 `dark` 而**页面仍亮**,唯一路径是 `useEffect` 里:

```ts
if (stored) {
  setTheme(stored === "dark" ? "dark" : "light"); // 只改 React state
  return; // 不碰 <html> class
}
```

——**只改 state、不碰 DOM class**,完全寄望内联脚本已设好 class。图标(state=dark)因此是月亮,
而 `<html>` 没有 `.dark`(页面亮)。

去构建产物 `.next/server/app/applications.html` 看实际渲染的内联脚本,**实锤根因**:

```js
// 产物里是:
localStorage.getItem(undefined); // ← key 是 undefined!
```

`THEME_STORAGE_KEY` 在**构建时**变成了 `undefined`,`JSON.stringify(undefined)` → `undefined`,
内联脚本永远读不到存储的主题 → 刷新时 `<html>` 不加 `.dark` → 页面亮。
而 `useEffect` 从 client 模块直接 import 同一常量(值正常 `"anp.theme"`)→ 读到 dark → 图标月亮。
**精确解释了「刷新变亮、图标仍月亮」。**

> 对照时间:`.next` 产于 `07-30 17:31`,`lib/theme-constants.ts` 修复于 `07-30 21:52`(commit
> `495cdf9 fix: …主题刷新丢偏好根因`)。**运行的是修复前的陈旧构建**——`495cdf9` 把常量从 `"use client"`
> 模块挪到纯模块 `theme-constants.ts`(注释详述:server component 从 `"use client"` 模块导入「非组件」
> const,App Router server 侧拿到 undefined),源码修复有效,但旧产物未重建。

## 2. 方案

两层修复:根因(重建产物)+ 纵深防御(消除单点依赖)。

**(a) 根因 — 重建前端产物/镜像**:`495cdf9` 源码已正确,全新 `next build` 产物的内联脚本已是
`localStorage.getItem("anp.theme")`。线上需重建前端镜像,不能继续跑陈旧 `.next`。

**(b) 纵深防御 — `useEffect` mount 时主动对齐 DOM**:旧实现 `stored` 分支只 `setTheme` 不碰 DOM,
内联脚本是**单点依赖**,一旦再因任何原因失效(CSP 拦截 / 产物过期 / 打包异常)同样症状复现。
新增 `setThemeClass(theme)`(只同步 `<html>` class、**不写 localStorage**,避免覆盖「跟随系统」语义),
mount 时无条件 `setThemeClass(initial)`:

- 内联脚本正常 → 幂等,无副作用;
- 内联脚本失效 → hydration 后立即纠正 DOM,杜绝刷新变亮。

同时把 `if (stored)`(truthy)收窄为 `stored === "light" || stored === "dark"`,与纯函数 `resolveTheme`
的「非法 stored 当无 stored」语义一致(垃圾值不再被误当「用户已选」),并让 effect 复用 `resolveTheme`
(此前该纯函数仅测试引用)。

## 3. 改动

- `platform/frontend/lib/theme.tsx`
  - 新增 `setThemeClass(theme)`:DOM-only 同步 `<html>.dark`(不持久化)。
  - `applyTheme` 改为复用 `setThemeClass`。
  - `useEffect` 重写:mount 时 `resolveTheme(stored, mql.matches)` 算出主题 → `setThemeClass` + `setTheme`
    兜底对齐;合法 stored 则停跟系统,否则继续监听 `prefers-color-scheme` 变化。
- `platform/frontend/lib/theme-constants.ts`:无改动(commit `495cdf9` 已修)。
- 文档:本记录。

## 5. 经验

- **「单点依赖 + 陈旧构建」是最隐蔽的一类回归**:源码已修、单测也过(单测只测源码不测产物),
  但跑的是修复前的产物 → 线上仍坏。排查前端「刷新后状态丢失」必须去**实际构建产物**里看内联脚本,
  不能只读源码。
- 防 FOUC 内联脚本与 React effect **两层都要能独立把 DOM 对齐正确**,任一层失效另一层兜底,
  不能让 effect 默默假设「脚本已经设好了」——本次 `stored` 分支只 `setTheme` 就是这个假设的漏洞。
- server component 导入值:从 `"use client"` 模块导入「非组件」const,App Router server 侧得 undefined;
  纯常量要放无 `"use client"` 的纯模块(`theme-constants.ts` 注释已记录,勿再踩)。

## 实际实现摘要

### 模块结构（新建 `internal/quota/`）

| 文件                                | 职责                                                                                                                       |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `model.go`                          | `Quota` / `Usage` 结构 + 默认值常量（与迁移 000003 对齐：20/20/10240/10000）                                               |
| `errors.go`                         | `QuotaExceededError{Dimension,Used,Limit,Unit}` + `IsQuotaExceeded/AsQuotaExceeded`                                        |
| `store.go`                          | `Get / GetOrCreate(ON CONFLICT 兜底并发) / Set(ErrNotExists)`                                                              |
| `service.go`                        | `CheckApps / CheckDatabases / CheckCapabilityToday / CheckDBSize / Usage / Set`；`InstanceLookup + PGSizeChecker` 接口注入 |
| `handler.go`                        | `GET/PUT /project-spaces/:id/quota`                                                                                        |
| `store_test.go` / `service_test.go` | PG 测试（testutil，禁 sqlite）                                                                                             |

`InstanceLookup` / `PGSizeChecker` 抽象保证 `quota` 不导入 `pgsupply/appdeploy/capability`，无循环依赖。

### pgsupply 适配

- `PGAdmin` 接口加 `DatabaseSizes(ctx, adminURL, dbNames)`：连 admin url，`SELECT datname, pg_database_size(datname) WHERE datname = ANY($1)`。`pqArray([]string)` 自拼 PG `text[]` 字面量，避免引 pgx 数组依赖。
- `QuotaAdapter`（薄包装 `Store`）实现 `quota.InstanceLookup`，返回项目首个 active PG 实例的 admin_url。
- `Provisioner` 加 `QuotaChecker` 接口；`Provision` 最前调 `CheckDatabases` + `CheckDBSize`，超限不建任何记录。

### 4 接入点

| 接入点                                       | 拦截维度            | 返回                                                     | 业务码 |
| -------------------------------------------- | ------------------- | -------------------------------------------------------- | ------ |
| `appdeploy.Create`（EnsureRepo 前）          | apps                | 409                                                      | 40950  |
| `pgsupply.Provision`（CreateAppDB 前）       | databases / db_size | Provision 失败 → appdeploy 写到 `application.last_error` | —      |
| `capability.Invoke`（技能校验后 / 调模型前） | capability_today    | 429                                                      | 42950  |
| 库大小巡检                                   | —                   | 放 3b                                                    | —      |

### main.go 装配

```go
quotaStore := quota.NewStore(database)
quotaSvc := quota.NewService(quotaStore, pgsupply.NewQuotaAdapter(pgsupplyStore), pgAdmin)
pgProvisioner := pgsupply.NewProvisioner(..., quotaSvc)
capabilityGateway := capability.NewGateway(..., quotaSvc)
appDeployHandler := appdeploy.Register(..., quotaSvc)
quota.Register(v1, quotaSvc, v)
```

## 顾虑 / 后续

- **多 PG 实例查询**：当前 `GetInstanceByProject` 只取首个 active 实例（单实例假设），未来若多实例需循环查每实例大小求和。3b 改。
- **capability 配额拦截路径**：全局 `AuthUser` 中间件强制 JWT，调 invoke 时需同时带 `Authorization: Bearer <登录token>` + `X-Api-Key: <APIKey>` 双 header。前端 invoke 体验可优化（封装客户端 APIKey 选择）。
- **库大小查询频率**：每次 `GET /quota` 都连 PG 实例查 `pg_database_size`，规模大时有开销。本阶段可接受（管理页非高频）；3b 可加缓存。
- **配置默认值演化**：改默认值只影响新建项目（GetOrCreate 已存在行不变）。如需批量改，加 admin 工具（3b）。
- **库大小巡检 / 告警**：本阶段只在建库时拦；已存在库涨满不会主动告警。3b 加定时任务 + ops 告警。

# 应用部署界面 tab 化改版 Design

**日期**：2026-08-19　**状态**：待用户审阅
**关联**：`docs/详细设计/功能-应用全景视图与部署中枢.md`（全景 P1/P3 之上的交互层改版）

## 1. 背景与目标

`/applications` 现为长单列流：每个应用一个大块（状态徽章/部署操作/DevWizard/构建日志/拓扑图/三栏 Detail/部署历史时间线），应用一多需长滚动找应用，操作与状态分散。`page.tsx` 已 2369 行。

**目标**：一个应用一个小 tab 页；tab 内 test/prod 部署实例左右并排；信息更集中。保留「一眼看全部应用」的能力（总览条）。

**非目标**：不改后端 API；不重写既有功能块的行为（导入向导/DevWizard/三栏 Detail/拓扑原样平移）；不引 WebSocket/新状态管理/图表库。

## 2. 布局架构（方案 3：混合——总览条 + 应用 tab）

```
┌──────────────────────────────────────────────────────┐
│ 工具条：📥导入/新建 · 筛选(状态/模式) · 说明(折叠)     │  常驻一行
├──────────────────────────────────────────────────────┤
│ 应用总览条（横向滚动，每应用一格）：                    │  新增
│ [●应用A v3 T✓P✓] [●应用B v1 T✗] [●应用C …]           │  点击=切 tab
├──────────────────────────────────────────────────────┤
│ ╔═ 应用A ══════════════════════════════ [✕关闭tab] ╗═╗│
│ ║ 状态头: 名字·状态徽章·v3·image·最近部署摘要          ║│
│ ║ ┌─── 🧪 test ───────────┐ ┌─── 🚀 prod ──────────┐ ║│
│ ║ │ v3 running :9103 URL  │ │ v2 running :9201 URL │ ║│
│ ║ │ [部署][构建日志][重试] │ │ [上线/部署][重试]     │ ║│
│ ║ │ 部署历史(按env过滤)    │ │ 部署历史(按env过滤)   │ ║│
│ ║ └───────────────────────┘ └──────────────────────┘ ║│
│ ║ [拓扑图] [需求|变更|发布 三栏] [env编辑] [DevWizard]  ║│
│ ╚═════════════════════════════════════════════════════╝│
└──────────────────────────────────────────────────────┘
```

- **总览条**：每应用一格（名字+状态色点+版本+环境迷你状态 `T✓/P✓`），点击切对应 tab；是唯一的「一眼看全部」入口。
- **tab 区**：同一时刻只渲染**激活**的一个应用工作区；`✕` 关闭 tab 后回总览（无选中态）。多 tab 可同时打开，非激活 tab 不渲染（保内存）。
- **环境并排卡**：现有 test/prod `grid sm:grid-cols-2` 卡（page.tsx:1794 起）升级为 tab 主体——各自吸附**本环境**的操作按钮 + **按 env 过滤的部署历史时间线**（P3 `deploy_history` 数据，前端过滤）。
- **external（纳管）应用**：无环境卡，显示探活卡（现状逻辑平移）。

## 3. 组件拆分与文件结构（含行数预算——单文件纪律）

```
app/applications/
├── page.tsx                    # 壳：工具条+总览条+tab容器+state 编排（≤450 行）
├── _lib/
│   ├── app-tabs.ts             # tab 开合/去重/选中/关闭 纯逻辑
│   ├── overview.ts             # 总览格子 model 推导（app+instances+stats→格子）
│   └── app-tabs.test.ts        # 上述两模块 vitest
├── _components/
│   ├── overview-bar.tsx        # 总览条（受控：apps/activeId/onSelect）≤150 行
│   ├── app-tab-panel.tsx       # 单应用工作区容器（状态头+编排）≤400 行
│   ├── env-deploy-card.tsx     # 环境并排卡（实例+操作+env 过滤时间线）≤300 行
│   └── topology-section.tsx    # TopologySection 原样迁出
└── 其余既有大块（导入向导/DevWizard/三栏 Detail/env 编辑）
    → 原样平移进独立文件或 app-tab-panel，行为零变化，diff 等价评审
```

拆分原则：新交互逻辑全进 `_lib/` 纯函数（vitest 覆盖）；既有大块**平移不重写**；组件只依赖注入 props（如 `EnvDeployCard{app, env, instance, history, onDeploy, onRetry, onLogs}`），不直接拉 API。

## 4. 数据流与轮询

- 总览条数据 = 现有 `load()` 全量列表 + 既有 5s 轮询**不动**（零新增请求）。
- tab 内 Detail/时间线：打开 tab 时拉（现有 `openDetail`）；随全局轮询刷新但**仅激活 tab**；非激活 tab 切换激活时重拉一次。
- 构建中/preparing spinner 轮询逻辑不变。
- `openDetail` 失败：toast + tab 保持打开，内容区给重试按钮；总览条数据失败沿用现有空态。

## 5. 测试与验收

- vitest：`_lib/` 纯逻辑（tab 开/切/关/去重；总览格子推导含 external/无实例边界）；既有 47 用例全绿。
- `tsc --noEmit` 0 错误、`next build` 通过、eslint 0 新增 warning。
- 平移块以「diff 等价」为评审口径（不改行为）。
- .28 部署后浏览器 e2e（用户）：总览条切 tab、test/prod 并排卡操作、时间线按 env 过滤、external 探活卡、构建中 spinner、`/ops/deploy-stats` 不受影响。

## 6. 风险与决策记录

- **为什么不拆独立路由**（`/applications/[id]`）：tab 常驻平台内切换更顺手（与编码工作台 tab 系统一致的交互习惯），且总览条与 tab 同页零跳转。
- **为什么总览条不做搜索**：现有应用量级（<20）横向滚动足够，YAGNI。
- **行数预算**：page.tsx 2369 → 壳 ≤450；本 spec 是「单文件纪律」规则（2026-08-19 用户定，组件目标 ≤400 行）的首次落地样板。

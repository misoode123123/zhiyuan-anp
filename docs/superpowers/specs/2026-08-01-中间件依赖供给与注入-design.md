## 1. 背景与问题

### 1.1 最后一公里断点

opencode 导入适配已落地（commit bec683a/cbea32f，.28 live e2e 验证通过）：导入项目后，opencode 按 `AGENTS.md`「ANP 部署适配规范」把应用代码改成 **env-over-config**——读 `PORT`/`REDIS_ADDR`/`DATABASE_URL`/`MILVUS_ADDR` 等环境变量，不再写死 `127.0.0.1`。

但 ANP 部署注入链路当前**只经 pgsupply 注入 `DATABASE_URL`**：

```
appdeploy_env 写入方（已穷举）：
  ① pgsupply.Provisioner.Provision  → DATABASE_URL（is_secret=true）  ← 唯一中间件供给
  ② Handler.UpsertEnv（/apps/:aid/env 面板）→ 用户手填
部署注入：handler.go:1607 EnvPairs() 读全表 → deployer.go:162 拼成 docker run -e
```

`REDIS_ADDR`/`MILVUS_ADDR` 等：规范文档（`standard/model.go:100`、`standards_seed.go:87`）**宣称**"ANP 可注入"，但**没有任何模块在 `appdeploy_env` 写这两个 key**。于是适配后的应用部署仍跑不起来——代码会读 `REDIS_ADDR`，但容器里根本没有这个 env。这是「导入适配」真正闭环的最后一公里。

### 1.2 顺带暴露的语义隐患

`appdeploy_env` 表只有 `is_secret`，**无 `scope`/`source` 字段**；`UNIQUE(app_id,key)` + `UpsertEnv` 的 `ON CONFLICT DO UPDATE` = **last-write-wins，平台/用户 env 不分**。用户在前端面板把 `DATABASE_URL` 改错或删了，会直接覆盖 pgsupply 注入值，无任何"系统 env 保护"。本设计一并修复（加 `source` + 部署时 reconcile 平台优先）。

### 1.3 .28 现状（已就位的中间件）

部署机 10.10.0.28 上已在跑（`0.0.0.0:端口`，容器可达）：

| 服务   | 容器/地址                                        | 用途                          |
| ------ | ------------------------------------------------ | ----------------------------- |
| Redis  | yxt-redis `10.10.0.28:6381`                      | 缓存/会话                     |
| Milvus | yxt-milvus `10.10.0.28:19530`                    | 向量库                        |
| PG     | yxt-pgsql `10.10.0.28:5434` + 平台供给的项目实例 | 关系库（DATABASE_URL 已注入） |

## 2. 目标与关键决策

### 核心原则

> **应用声明依赖（适配回写），平台按策略供给连接信息并注入 env；应用侧只读 env，无需 host 网络。** 复用 pgsupply 范式（实例管理 + 管控客户端 + 经 `EnvWriter` 写连接串），扩到 redis/milvus 等中间件。

### 已锁定决策

| 维度          | 选择                                                                       | 理由                                                                    |
| ------------- | -------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 供给策略范围  | **全量 dedicated + shared + bind-existing**（PRD §4.4 三策略）             | 平台级能力，对应 PRD §7 ②；redis/milvus 各策略类比 pgsupply             |
| 注入判定      | **适配驱动回写**（opencode 适配后写 `.anp/deps.yaml` 清单）                | 导入适配是主驱动；opencode 读完代码才知道应用要什么                     |
| PG 归属       | **仍走 pgsupply**（DATABASE_URL 不动）                                     | 已 work，避免动稳定链路；mwsupply 管 redis/milvus/可扩展 kind，双轨并存 |
| 注入机制      | **表驱动**（写 `appdeploy_env` 行，`EnvPairs` 已读全表）                   | 部署主流程零改造（Deployer/EnvPairs 不改）                              |
| 平台 env 保护 | **加 `source` 字段 + 部署 reconcile 平台优先**                             | 治用户面板误改 DATABASE_URL 隐患                                        |
| 声明/供给分离 | 声明在 adapt 完成钩子（读清单→落 binding），供给在部署（reconcile→写 env） | 解耦代码世界与 DB 世界；deploy 不依赖 repo 目录访问；幂等               |

### 策略解析默认

清单可显式指定 `strategy`；不指定 → **`bind_existing`**（.28 有实例、最省、契合"导入最常见"，PRD §9#2 建议 bind+提示）；可按项目配默认。`dedicated`/`shared` 仅清单显式或项目策略要求时触发。

## 3. 总体架构

```
  导入应用 ──▶ pgsupply（DATABASE_URL，已有，不动）
           ──▶ SubmitAdapt（opencode 适配，改代码 + 写 .anp/deps.yaml）──┐
                                                                       │
  adapt 完成钩子 ◀────────────────────────────────────────────────────┘
     │ 读 .anp/deps.yaml → upsert appdeploy_service_binding(declared)
     ▼
  buildAndDeploy（部署）
     │ ① 中间件 reconcile（新增）：遍历 binding → 解析策略 → 幂等供给 → 写 appdeploy_env(source=platform)
     │ ② EnvPairs() 读全表（含新 REDIS_ADDR/MILVUS_ADDR）   ← 已有，不改
     │ ③ ensurePortEnv（PORT）                                ← 已有，不改
     ▼
  Deployer.Deploy → docker run -e ...（表驱动注入）
```

三策略供给源：

```
bind_existing ──▶ appdeploy_service_instance(supply_mode=bind_existing) ──▶ .28 yxt-redis/yxt-milvus（种子）
shared        ──▶ appdeploy_service_instance(supply_mode=shared) ──▶ 共享实例 + 每 app 隔离 token（db号/prefix）
dedicated     ──▶ docker run app 专属容器 ──▶ 注册进 appdeploy_service_instance(supply_mode=dedicated)
```

## 4. 数据模型

### 4.1 新增表 `appdeploy_service_instance`（中间件实例注册表）

平台级（`project_space_id` 可空 = 平台全局）+ 项目级。登记所有可绑定的中间件实例：bind-existing 目标、shared 共享池、dedicated 供给出来的专属实例。

```sql
CREATE TABLE appdeploy_service_instance (
    id               TEXT PRIMARY KEY,
    project_space_id TEXT REFERENCES project_space(id) ON DELETE CASCADE,  -- NULL=平台全局
    kind             TEXT NOT NULL,                 -- redis / milvus / ...（可扩展）
    name             TEXT NOT NULL,                 -- 人类可读名，如 "yxt-redis"
    supply_mode      TEXT NOT NULL,                 -- shared / bind_existing / dedicated
    host             TEXT NOT NULL,
    port             INT  NOT NULL,
    auth_ref         TEXT,                          -- 密码/token 的 secret 引用（明文，同 pgsupply I1 债，阶段3 vault/KMS）
    isolation        JSONB,                         -- 隔离配置：redis {db_range:[0,15]} / milvus {prefix_mode:"per_app"}
    status           TEXT NOT NULL DEFAULT 'active',-- active / draining / maintenance
    created_at       TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at       TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_svinst_ps_kind ON appdeploy_service_instance(project_space_id, kind, supply_mode);
CREATE INDEX idx_svinst_status ON appdeploy_service_instance(status);

-- 种子数据：.28 已有中间件（bind_existing 目标）
INSERT INTO appdeploy_service_instance (id, project_space_id, kind, name, supply_mode, host, port, isolation, status)
VALUES
  ('svinst-redis-28', NULL, 'redis',  'yxt-redis',  'bind_existing', '10.10.0.28', 6381,  '{"default_db":0}', 'active'),
  ('svinst-milvus-28',NULL, 'milvus', 'yxt-milvus', 'bind_existing', '10.10.0.28', 19530, NULL,               'active');
```

> **密码不入设计耦合**：若 .28 redis 有 AUTH，密码以 `auth_ref` 存（明文 secret 引用，与 pgsupply `pg_instance.admin_url_ref` 同模式、同债），连接串拼好后整体写入 `appdeploy_env`（`is_secret=TRUE`，接口 mask）。本期 .28 redis/milvus 若无鉴权则 `auth_ref=NULL`。

### 4.2 新增表 `appdeploy_service_binding`（每应用绑定 = 清单消费 + 供给结果）

```sql
CREATE TABLE appdeploy_service_binding (
    id                  TEXT PRIMARY KEY,
    app_id              TEXT NOT NULL REFERENCES appdeploy_application(id) ON DELETE CASCADE,
    project_space_id    TEXT NOT NULL,
    service_kind        TEXT NOT NULL,              -- redis / milvus / ...
    strategy            TEXT NOT NULL,              -- dedicated / shared / bind_existing（解析后）
    service_instance_id TEXT REFERENCES appdeploy_service_instance(id),  -- shared/bind 指向注册实例；dedicated 供给后回填
    isolation_token     TEXT,                       -- 分配到的隔离 token：redis db号 / milvus collection 前缀
    env_key             TEXT NOT NULL,              -- 注入的 env key：REDIS_ADDR / MILVUS_ADDR / ...
    status              TEXT NOT NULL DEFAULT 'declared', -- declared（清单已声明）/ bound（已供给写 env）/ failed
    last_error          TEXT,
    created_at          TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at          TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE (app_id, service_kind)                   -- 每应用每 kind 一个绑定
);
CREATE INDEX idx_svbind_app ON appdeploy_service_binding(app_id);
CREATE INDEX idx_svbind_ps  ON appdeploy_service_binding(project_space_id);
```

### 4.3 改 `appdeploy_env`（加 source 列）

```sql
ALTER TABLE appdeploy_env
  ADD COLUMN IF NOT EXISTS source TEXT NOT NULL DEFAULT 'user';  -- user / platform
```

`UpsertEnv` 扩展为带 `source` 参数；语义见 §6.3（平台 env 部署时 reconcile，平台优先）。

## 5. 依赖清单（适配回写）

### 5.1 格式

仓库根 `.anp/deps.yaml`：

```yaml
# ANP 中间件依赖声明（由 opencode 适配回写，可手编）
services:
  - kind: redis # 必填：redis / milvus / ...
    # strategy: bind_existing   # 可选：dedicated / shared / bind_existing；不写走默认解析
  - kind: milvus
```

### 5.2 回写机制

- 扩 `AdaptPrompt`（`internal/appdeploy/adapt_prompt.go`）+ `AGENTS.md`「ANP 部署适配规范」段（`RefreshAgentsMD`）：要求 opencode 适配时**发现 redis/milvus 等中间件用法，就写/更新 `.anp/deps.yaml` 并提交**。
- opencode 只负责声明 WHAT（应用需要哪些 kind）；HOW（策略）由平台解析。
- **best-effort**：清单缺失/空 = 除 `DATABASE_URL` 外无额外注入，不阻塞部署。手编/UI 兜底（非适配创建的应用可经 UI 声明）。

### 5.3 声明落库（adapt 完成钩子）

adapt 完成处（`code_task` MarkCompleted → 现有「自动登记 change_request」同点）加 best-effort 钩子：

1. 读仓库 `.anp/deps.yaml`（适配提交后存在于 repo）
2. 解析 `services` → 对每个 kind `upsert appdeploy_service_binding(status=declared)`（同 kind 已存在则更新，不重复）
3. 失败不阻塞（best-effort，记日志）

## 6. 供给与注入流程

### 6.1 reconcile 步骤（buildAndDeploy 内，EnvPairs 之前）

`handler.go buildAndDeploy` 现有：`EnvPairs()` → `Deployer.Deploy`。在 `EnvPairs()` 前插入 `mwsupply.Reconcile(ctx, appID)`：

```
Reconcile(appID):
  bindings = ListBindings(appID)               -- 该 app 全部 service_binding
  for b in bindings:
    if b.status == bound and 实例健康: continue  -- 幂等：已绑定且实例在，跳过
    strategy = resolve(b.strategy)              -- 显式 → 否则 bind_existing 默认
    switch strategy:
      bind_existing: inst = LookupInstance(kind, project→platform) ; token=默认db/prefix
      shared:        inst = LookupShared(kind) ; token = AllocateToken(inst, appID)  -- redis db号 / milvus 前缀
      dedicated:     inst = ProvisionDedicated(appID, kind)  -- docker run 容器 + 分配端口 + 写注册表
    connStr = BuildConnStr(inst, token, auth)   -- redis: redis://host:port?db=N ; milvus: host:port
    EnvWriter.UpsertEnv(appID, b.env_key, connStr, isSecret=有鉴权, source=platform)
    update binding(status=bound, instance_id, token)
  -- 平台托管 env 保护：reconcile 后平台 key 必为正确值（平台优先）
```

### 6.2 三策略供给细节

| 策略            | 实例来源                                            | 隔离                                                                           | env 示例                                    | 生命周期                                  |
| --------------- | --------------------------------------------------- | ------------------------------------------------------------------------------ | ------------------------------------------- | ----------------------------------------- |
| `bind_existing` | 注册表 `supply_mode=bind_existing`（项目级→平台级） | 无（或 `isolation.default_db`）                                                | `REDIS_ADDR=10.10.0.28:6381`                | 实例外部管理，平台只注入                  |
| `shared`        | 注册表 `supply_mode=shared` 共享池                  | 每 app token：redis 分配 db 号（from `db_range`）；milvus 分配 collection 前缀 | `REDIS_ADDR=10.10.0.28:6381` + `REDIS_DB=7` | token 配额限制；删 app 回收               |
| `dedicated`     | `ProvisionDedicated` docker run app 专属容器        | 独占实例                                                                       | `REDIS_ADDR=<专属host>:<port>`              | app 删除 stop+rm（类比 pgsupply Cleanup） |

连接串构造（`mwsupply/connstr.go`）：

- redis：`REDIS_ADDR=host:port`（+ `REDIS_DB=N` 若隔离；+ `REDIS_PASSWORD` 若 AUTH，走 secret）
- milvus：`MILVUS_ADDR=host:port`
- 扩展 kind 各自定义 env_key 与构造规则（注册表式，便于加新中间件）

### 6.3 平台 env 保护语义（source 字段）

- `UpsertEnv(ctx, appID, key, value, isSecret, source)`：新增 `source` 参数。
- **部署 reconcile**：`mwsupply.Reconcile` 每次部署重写其托管 key（`source=platform`），保证平台值正确——即使用户在面板改过，下次部署恢复平台值（**平台优先**）。
- 前端 env 面板：`source=platform` 的行标注「平台托管」，禁手改/删除（只读展示，含 mask）；`source=user` 行可自由编辑。
- 用户仍可添加**自己的** key（`source=user`）；与平台 key 同名时，reconcile 以平台值为准。

## 8. 与 pgsupply 的关系（双轨，暂不 unify）

| 维度     | pgsupply（已有，不改）                 | mwsupply（新增）                      |
| -------- | -------------------------------------- | ------------------------------------- |
| 管       | PG                                     | redis / milvus / 可扩展 kind          |
| 注入 key | `DATABASE_URL`                         | `REDIS_ADDR` / `MILVUS_ADDR` / ...    |
| 实例模型 | 每项目独立 PG 实例（managed/external） | 注册表（bind/shared）+ dedicated 容器 |
| 声明     | 无（建应用即供给）                     | 适配清单驱动                          |
| secret   | `appdeploy_env is_secret`              | 同（+ source=platform）               |

> **未来债**：pgsupply 可 unify 进 mwsupply（PG 作为 kind=pg 的特例，DATABASE_URL 作其 env_key），但本期不动稳定链路。pgsupply 的 `UpsertEnv` 调用点（provisioner.go:87）同步加 `source=platform`。

## 11. 风险与取舍

| 风险                                     | 对策                                                               |
| ---------------------------------------- | ------------------------------------------------------------------ |
| 适配回写不可靠（opencode 不写/写错清单） | best-effort + UI/手编兜底 + 缺失不阻塞；adapt 完成钩子失败仅记日志 |
| dedicated 成本（每 app 起容器）          | 默认 bind_existing/shared；dedicated 按需 + 配额                   |
| shared 多租户隔离                        | db号/prefix + 配额 + 删 app 回收 + token 唯一约束                  |
| 平台 env 被用户覆盖                      | source 字段 + 部署 reconcile 平台优先 + UI 标注只读                |
| pgsupply/mwsupply 双轨维护               | 暂不 unify（避免动稳定 DATABASE_URL 链路），列未来债               |

## 13. 验收标准（P1）

1. **注册即种子**：迁移后 `appdeploy_service_instance` 含 .28 redis/milvus 两条 bind_existing 记录
2. **适配回写**：opencode 适配后 repo 出现 `.anp/deps.yaml`，adapt 完成后 `appdeploy_service_binding` 有 declared 行
3. **部署注入**：适配后部署，容器内 `REDIS_ADDR`/`MILVUS_ADDR` 指向 .28 实例，应用连通
4. **平台 env 保护**：`appdeploy_env.source=platform` 的行前端只读；用户面板改不了；部署 reconcile 恢复平台值
5. **零回归**：现有 `DATABASE_URL` 注入与部署主流程不受影响（pgsupply 仅加 source 参数）
6. **幂等**：重复部署不重复供给（binding=bound 且实例健康则跳过）

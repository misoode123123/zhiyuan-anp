## 1. 数据模型

迁移 `000037_deploy_history`：

```sql
CREATE TABLE deploy_history (
  id            BIGSERIAL PRIMARY KEY,
  app_id        TEXT NOT NULL,
  env           TEXT NOT NULL,           -- test / prod
  version       INT  NOT NULL,           -- 部署目标版本号（计数器值，失败不回退）
  engine        TEXT NOT NULL,           -- fixed / ai
  result        TEXT NOT NULL DEFAULT '', -- ''=在途 / success / failed
  operator      TEXT NOT NULL,           -- 触发用户名（CtxUserID）
  sha           TEXT,                    -- 构建提交（有则记，可空）
  image         TEXT,
  host_port     INT,
  duration_sec  INT,                     -- 开始→终态秒数（在途为 NULL）
  error_summary TEXT,                    -- 失败摘要 ≤200 字（last_error 头部）
  notes         TEXT,                    -- AI 链备注：回滚详情/验证失败步/绕过 shim 等
  created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  finished_at   TIMESTAMPTZ
);
CREATE INDEX idx_dephist_app ON deploy_history(app_id, created_at DESC);
CREATE INDEX idx_dephist_stat ON deploy_history(engine, result, created_at DESC);
```

语义：

- **一行 = 一次部署尝试**。开始时 INSERT（result=''），终态 UPDATE result/duration/finished_at。
- **result 三态口径**：`success` / `failed`（AI 链失败回滚成功也记 `failed`，回滚详情进 notes——统计「失败率」不被回滚成败稀释）/ 孤儿（见下）不进统计。
- **孤儿行**：backend 重启杀 goroutine 会留下 result='' 永不更新的行。查询侧跳过 `result=''` 且 `created_at` 超 30min 的行（统计与时间线都排除）；**不做后台清扫**（YAGNI，30min 阈值同时在时间线里把在途行展示为「部署中…」）。

## 2. 采集写入点（两链四处）

| 链   | 写点 | 位置（现有代码锚点）                                                          |
| ---- | ---- | ----------------------------------------------------------------------------- |
| 固定 | 开始 | `Deploy` handler 固定分支 `markBuilding` 处：INSERT（engine=fixed）           |
| 固定 | 终态 | `buildAndDeploy` 成功点（RecordActuals 后）/ panic recover / err 分支：UPDATE |
| AI   | 开始 | 分流处 `markPreparing` 后：INSERT（engine=ai）                                |
| AI   | 终态 | `aiDeploy` 成功 / `aiFail` / `aiFailWithRollback`：UPDATE（notes 记回滚）     |

- **operator** = `CtxUserID`（handler 上下文）；sha 从 `buildAndDeploy`/分流处现有参数透传。
- **UPDATE 定位**：按 (app_id, env, version) 唯一定位本次行（版本计数器失败不回退，同版本号不会重复尝试——P2 已确立）。
- **写失败一律 best-effort**：`zap.Warn` 后继续，不阻断部署（与 RecordActuals 失败处理一致）。
- Store 新增三方法：`InsertDeployHistory` / `FinishDeployHistory(appID, env string, version int, result, errSummary, notes string, finishedAt, duration)` / `ListDeployHistoryByApp` / `DeployStats(engine 维度聚合)`。

## 3. 展示

### 3.1 详情页时间线（全景视图内嵌）

- `Store.Detail()` 聚合加 `DeployHistory []DeployHistoryItem`（最近 20 条，`result=''` 且 <30min 的在途行展示为「部署中…」）。
- `/detail` 响应扩一节；前端全景视图「部署实例」列下加**可折叠时间线**：每行=时间+版本徽标（vN）+engine 图标（🔧 固定 / 🤖 AI）+result 色（绿 success/红 failed/黄部署中）+耗时+operator；点开展开 error_summary/notes。

### 3.2 AI 统计独立页（运维侧）

- 路由：`/ops/deploy-stats`（运维侧边栏新入口「部署统计」）。
- API：`GET /api/v1/appdeploy/deploy-stats?days=30`，按 engine 分组返回：
  - 成功率（success / (success+failed)）
  - 平均/中位耗时（duration_sec）
  - 失败 top 原因：error_summary 词频 top5（简单分词：按标点切+取 ≥4 字片段）
  - 近 N 天每日 trend：日期、每 engine 的 success/failed 计数
- 前端简单表格式呈现（成功率大数字卡 + 每日计数表），**不做图表库**（YAGNI）。

## 4. 错误处理

- 写 `deploy_history` 失败（表不存在/DB 抖动）：Warn 日志，部署链照常——可观测采集**永不反噬主链**。
- 统计 API：空表返回零值结构（不 500）。
- `days` 参数钳制 1–90，默认 30。

## 5. 测试策略

- **纯单测（PG anp_test）**：Store 三方法 CRUD 往返；孤儿行过滤（造 result='' 超 30min 行，List/Stats 均排除）；Stats 聚合正确性（成功/失败/耗时均值中位/top 原因/daily trend 各断言）。
- **集成**：`TestDeploy_HistoryWritten`——走 `Deploy` handler（fixed 链，仿 ai_engine_test 的 newHTTPHandler 模式）断言成功后 history 行 result=success+duration>0；AI 链复用 `TestAiDeploy_FullChain` fake 断言 history 行 engine=ai。
- **.28 e2e**：部署一次（fixed 一次、ai 一次）→ 详情页时间线两行可见 → /ops/deploy-stats 出成功率；杀一次 backend 制造孤儿行确认不进统计。

## 6. 关键决策记录

| 决策               | 选择                        | 理由                                                |
| ------------------ | --------------------------- | --------------------------------------------------- |
| 采集架构           | 同步直写（方案 A）          | 与 aiLog/operation_log 模式一致；事实在链内强一致   |
| 回滚成功的 AI 失败 | 记 failed，回滚详情进 notes | 失败率口径不被回滚稀释                              |
| 存量回填           | 不回填                      | 无可信源；上线即始                                  |
| 孤儿行             | 查询侧 30min 过滤，不清扫   | 最少活动件；在途行兼作「部署中」展示                |
| UPDATE 定位        | (app_id, env, version)      | 版本计数器失败不回退保证唯一                        |
| 统计页形态         | 表格式，不引图表库          | YAGNI                                               |
| 监控趋势/健康 SLA  | 留 P3.5                     | 本期聚焦；Stats()/HealthReconciler 钩子已在，加即用 |

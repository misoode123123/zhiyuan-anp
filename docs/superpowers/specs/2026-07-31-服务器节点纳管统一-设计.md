# 设计:服务器节点纳管统一(Linux Docker + Windows 原生 SSH)

| 版本 | 日期       | 作者     | 状态   |
| ---- | ---------- | -------- | ------ |
| v0.1 | 2026-07-31 | ANP 团队 | 待审核 |

## 1. 背景

ANP 平台纳管 Linux + Windows 服务器节点,用于开发/测试/生产。每个节点需同时:

1. **管理服务器** —— 看板看到 OS 状态/指标(CPU、内存、磁盘)。
2. **部署应用** ——
   - Linux 节点:通过 **Docker** 部署(已有 `docker_tcp` 链路)。
   - Windows 节点:应用只支持 Windows 平台,**直接部署到 Windows 服务器**(无 Docker,走 SSH)。

## 2. 现状与缺口

| 项                     | 现状                                                                                         | 缺口                                      |
| ---------------------- | -------------------------------------------------------------------------------------------- | ----------------------------------------- |
| 节点模型               | `connect_type` 一个字段焊死「部署方式+监控方式」                                             | 解耦:部署走 docker_url/ssh,监控走 OS 凭证 |
| Linux docker 主机(.30) | docker_tcp → monitor 直接跳过,无 OS 指标、采集按钮灰                                         | 要同时出 OS 指标 + docker 容器数          |
| Windows 采集           | WinRM 走 go-ntlmssp,Server 2016/2022 都 401(库硬伤,原生 PSRemoting 可连,Go 库复刻 NTLM 不动) | 改走 SSH(等 win-ssh)                      |
| Windows 部署           | NativeDeployer 已支持 SSH(PutFile+Run),未端到端验                                            | 验证 + 打包方式                           |
| 编辑表单               | docker_tcp 不填 OS 凭证(「不符合常规」)                                                      | 凭证字段对所有类型显示                    |
| 看板                   | 只显 OS 指标,无 docker 容器信息                                                              | docker_tcp 节点补容器数                   |

### 2.1 为什么放弃 WinRM 统一(保留为备选)

WinRM 跨版本差异是结构性的:Server 2008 R2/WinRM 2.0、2012/3.0、2016、2019/2022(NTLM 安全加固要求 MIC,拒 go-ntlmssp 的 type3)。组合爆炸(NTLM 版本、MIC、AllowUnencrypted、TrustedHosts、LocalAccountTokenFilterPolicy、Kerberos vs NTLM),Go 客户端无法一套覆盖。实测 go-ntlmssp 在 2016 与 2022 都 401。

**SSH 天然统一**:OpenSSH 在所有 Windows Server 版本协议一致(2008 R2/Win7 起 Win32-OpenSSH 便携版,2019+ 自带)。一个 Go SSH 客户端 + 一套密码/key 认证 + 同一条 `powershell -Command`,覆盖所有版本,无版本分支。

## 3. 设计

### 3.1 节点模型:部署与监控解耦

```
节点
├─ 部署:connect_type
│   ├─ docker_tcp → deployer 用 docker_url(docker -H)
│   ├─ ssh        → NativeDeployer 用 ssh 凭证(Linux + Windows)
│   └─ winrm      → (备选保留;采集 401 已知限制,错误已透传)
└─ 监控:OS 凭证(与 connect_type 无关)
    ├─ 有 ssh 凭证   → SSHExecutor 采 OS(优先)
    ├─ 有 winrm 凭证 → WinRMExecutor 采(WinRM 仍 401,实际走 ssh)
    └─ 无凭证 / node_local → 跳过 / 本地 /host/proc
```

- `connect_type` 决定**部署方式**;`ssh_*`/`winrm_*` 凭证决定**监控方式**。两者独立。
- `.30(Linux docker)`:connect_type=docker_tcp(部署走 Docker)+ 填 SSH key(监控走 SSH)→ 一张卡同时出 OS 指标 + docker 容器数。
- `Windows`:connect_type=ssh + 填 ssh_password → 部署与监控都走 SSH,与版本无关。

### 3.2 OS 采集分派(与 connect_type 解耦)

新增 `NewOSExecutor(n)`:按 OS 凭证选 executor(ssh 凭证优先于 winrm),与 connect_type 无关。`monitor.collectNode` 用它;无凭证且非 node_local 才跳过。

```
NewOSExecutor(n):
  if n.ID == "node_local": return nil (走 localCollectNode)
  if n.SSHPassword != "" or n.SSHKey != "": return SSHExecutor
  if n.WinRMPassword != "": return WinRMExecutor
  return nil  // 无 OS 凭证,跳过采集
```

`Start()` 去掉「docker_tcp 无脑跳过」逻辑,改为「NewOSExecutor 返回 nil 才跳过」。

### 3.3 docker 容器数(docker_tcp 节点)

metric 加 `container_count`。docker_tcp 节点采集时,若 `docker_url` 非空,跑 `docker -H <docker_url> ps -q | wc -l`(经 docker API)填 `container_count`;前端卡显容器数。无 docker_url 的节点不采集此项。

> v1 只采集容器**数量**(一个数)。完整容器列表(名称/状态/镜像)不在本期范围,作为后续扩展。

### 3.4 前端 /servers

- 凭证字段(ssh_user/ssh_password/ssh_key、winrm_user/winrm_password/winrm_port)对**所有 connect_type** 显示(含 docker_tcp),docker_tcp 也能填 OS 凭证。
- 采集按钮「有 OS 凭证就启用」(去掉「docker_tcp 一律灰」);无凭证才灰。
- docker_tcp 节点卡片显 `container_count`(容器数)。
- 修误导文案:docker_tcp 无凭证时显「docker_tcp 节点走宿主本地监控,不远程采集」。

## 6. WinRM 处置

- `connect_type=winrm` **保留**(不删),作为备选(装不了 OpenSSH 或偏好 WinRM 的场景)。
- WinRM 采集 401(go-ntlmssp 与现代 Windows Server 不兼容)**暂不修**,作为已知限制;错误已透传,用户配 winrm 节点会看到「401 - invalid content type」。
- 未来若要修,走「补 MIC + MsvAvFlags 到 go-ntlmssp type3」(go.mod replace 到本地补丁版),见 `docs/bugs/2026-07-30-winrm采集401与主题刷新丢偏好.md`。

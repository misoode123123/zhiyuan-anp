# 服务器管理板块（纳管/自动搭建/部署/监督/分组）

> 日期:2026-07-30 ｜ 状态:待评审

## 1. 背景与目标

ANP 平台当前部署能力只支持单台 .28（`node_local`，docker socket）+ 远程 docker tcp 节点（`deploy_node` 表已有 `docker_url`/`ssh_user`/`TestDocker` 接口）。但远程只支持 Docker tcp:2375（节点须预装 Docker + 开放 2375），不支持 SSH/WinRM；不自动搭建环境；无资源/健康监督看板；无 dev/test/prod 分组。

**目标**：升级现有 `DeployNode` 机制成正经的"服务器管理"板块——纳管 dev/test/prod 服务器，SSH/WinRM 远程连接后自动搭建环境（Linux 装 Docker；Windows 原生不装），带 `deploy.yaml` 部署描述的原生应用按描述生成部署脚本远程执行（不限类型），主动采集资源/健康做监督看板，按 dev/test/prod 分组管理。

## 2. 已确认的需求边界

| 维度 | 选择                                                                 |
| ---- | -------------------------------------------------------------------- |
| 范围 | 全做：纳管 + 自动搭建 + 部署 + 监督 + dev/test/prod 分组             |
| 平台 | Linux（SSH + 装 Docker）+ Windows（WinRM + 原生，不装 Docker）       |
| 搭建 | Linux 装 Docker；Windows 只验连通 + 探测（不装 Docker）              |
| 部署 | 抽象 NativeDeployer 接口 + 项目 `deploy.yaml` 部署描述驱动，不限类型 |
| 监督 | 主动 SSH/WinRM 采集（不装 agent）                                    |
| 分组 | dev / test / prod                                                    |

## 3. 节点数据模型 + 远程执行抽象

### 3.1 DeployNode 扩展（迁移 000023）

`deploy_node` 加列（幂等）：

```sql
ALTER TABLE deploy_node ADD COLUMN IF NOT EXISTS os_type TEXT NOT NULL DEFAULT 'linux';            -- linux / windows
ALTER TABLE deploy_node ADD COLUMN IF NOT EXISTS env TEXT NOT NULL DEFAULT 'dev';                 -- dev / test / prod
ALTER TABLE deploy_node ADD COLUMN IF NOT EXISTS connect_type TEXT NOT NULL DEFAULT 'docker_tcp'; -- docker_tcp(现有) / ssh / winrm
ALTER TABLE deploy_node ADD COLUMN IF NOT EXISTS ssh_port INT NOT NULL DEFAULT 22;
ALTER TABLE deploy_node ADD COLUMN IF NOT EXISTS ssh_key TEXT;        -- SSH 私钥(PEM,可选;空=平台默认 ~/.ssh/miscode)
ALTER TABLE deploy_node ADD COLUMN IF NOT EXISTS winrm_user TEXT;     -- WinRM 用户
ALTER TABLE deploy_node ADD COLUMN IF NOT EXISTS winrm_password TEXT; -- WinRM 密码(明文存DB,本期简化;后续加密)
ALTER TABLE deploy_node ADD COLUMN IF NOT EXISTS last_seen TIMESTAMPTZ;
```

`DeployNode` struct 加对应字段。存量节点（node_local 等）默认 `os_type=linux`/`env=dev`/`connect_type=docker_tcp`，零影响。`node_local` 调整 `env=test`（.28 是测试环境）。

### 3.2 RemoteExecutor 接口（`internal/appdeploy/remote_executor.go`）

```go
// RemoteExecutor 远程命令执行 + 文件传输抽象。
// SSHExecutor/WinRMExecutor 各实现一套；部署器/监督/provisioning 都经此，不直接碰协议。
type RemoteExecutor interface {
    Run(ctx context.Context, cmd string) (stdout, stderr string, exitCode int, err error)
    PutFile(ctx context.Context, localPath, remotePath string) error
    TestConnection(ctx context.Context) error
}

// NewRemoteExecutor 按 node.ConnectType 返回对应执行器。
func NewRemoteExecutor(n *DeployNode) (RemoteExecutor, error)
```

- `SSHExecutor`：`golang.org/x/crypto/ssh`，私钥用 `n.SSHKey`（空则平台默认）。`Run`=SSH exec；`PutFile`=SCP/SFTP。
- `WinRMExecutor`：`github.com/masterzen/winrm`，用 `n.WinRMUser/Password`。`Run`=WinRM command；`PutFile`=WinRM 上传（小文件 base64+命令重建，大文件分块）。
- 现有 `docker_tcp` 节点不走 RemoteExecutor（仍用 `docker -H tcp://...`），保持兼容。

### 3.3 关键约束

- 凭证敏感：WinRM 密码、SSH 私钥本期明文存 DB（列表 API 返回时掩码）。后续接加密（留备注）。
- `NewRemoteExecutor` 按 connect_type 分派，未知类型报错。
- RemoteExecutor 是纯接口，可注入 fake 单测。

## 4. 自动环境搭建

### 4.1 Provisioner（`internal/appdeploy/provision.go`）

```go
type Provisioner struct{}
// Provision 搭建环境，返回结果摘要 + 日志。
func (p *Provisioner) Provision(ctx context.Context, n *DeployNode, exec RemoteExecutor) (log string, err error)
```

### 4.2 Linux provisioning（装 Docker，SSH）

```bash
. /etc/os-release
if command -v docker >/dev/null 2>&1; then echo "docker already installed";
elif command -v apt-get >/dev/null 2>&1; then
  apt-get update -qq && apt-get install -y -qq docker.io && systemctl enable --now docker
elif command -v yum >/dev/null 2>&1; then
  yum install -y docker && systemctl enable --now docker
else echo "unsupported distro"; exit 1; fi
docker version --format '{{.Server.Version}}'
```

装完 Docker，后续部署可通过 SSH 跑 `docker`（替代 tcp:2375），更安全。

### 4.3 Windows provisioning（不装 Docker，WinRM 验连通 + 探测）

```powershell
$env:COMPUTERNAME
Get-Command dotnet -ErrorAction SilentlyContinue | Select-Object -ExpandProperty Source
Get-Service W3SVC -ErrorAction SilentlyContinue | Select-Object Status
```

**不在 Windows 装 Docker**。若应用部署描述要求 .NET/IIS 且未装，部署阶段（§5）按描述步骤装（可选 `choco install`）。

### 4.4 状态机 + 接口

- `DeployNode.Status` 加值：`provisioning` / `ready` / `provision_failed`。现有 `active` 保留（等价 ready）。
- `POST /deploy-nodes/:nid/provision` → 异步跑 Provision → 更新 status + last_seen + 日志。
- provisioning 异步（goroutine），前端轮询节点状态。

### 4.5 关键约束

- 幂等：重复 provision 不报错（已装跳过）。
- Linux 装失败（distro 不支持/无 sudo）→ `status=provision_failed` + 错误日志。
- Windows 不装 Docker，provision 主要是连通验证 + 探测；真正的环境准备按部署描述在部署阶段做。
- provision 日志存 DB，前端可查看。

## 5. 部署描述 + 抽象部署器

### 5.1 部署描述 schema（`deploy.yaml`，存应用 RepoDir）

```yaml
target:
  os: linux # linux / windows / auto（auto=按节点 OS）
  dir: /opt/myapp # 远端部署目录
steps:
  - transfer: # 传输产物文件
      from: "dist/*" # 本地(RepoDir 或构建产物)glob
      to: "{{target.dir}}/"
  - run: # 执行命令
      cmd: "chmod +x myapp && ./myapp --daemon"
      cwd: "{{target.dir}}"
  - service: # 可选：注册系统服务
      name: myapp
      start: "./myapp --daemon"
      autostart: true
  - healthcheck: # 可选：健康检查
      cmd: "curl -sf http://localhost:8080/health || exit 1"
      timeout: 30s
```

Windows 版同理，`cmd` 用 PowerShell。`service` 步骤按 OS 翻译：Linux→systemd unit，Windows→`sc create`/nssm。

### 5.2 DeployDesc struct（`internal/appdeploy/deploy_desc.go`）

```go
type DeployDesc struct {
    Target TargetDesc `json:"target" yaml:"target"`
    Steps  []StepDesc `json:"steps" yaml:"steps"`
}
type TargetDesc struct{ OS, Dir string }
type StepDesc struct {
    Transfer    *TransferStep    `json:"transfer,omitempty"`
    Run         *RunStep         `json:"run,omitempty"`
    Service     *ServiceStep    `json:"service,omitempty"`
    Healthcheck *HealthcheckStep `json:"healthcheck,omitempty"`
}
// TransferStep{From, To}；RunStep{Cmd, Cwd}；ServiceStep{Name, Start, Autostart}；HealthcheckStep{Cmd, Timeout}
```

解析用 `gopkg.in/yaml.v3`。

### 5.3 NativeDeployer（`internal/appdeploy/deployer_native.go`）

```go
type NativeDeployer struct{}
// RenderScript 按节点 OS 把 DeployDesc 翻译成脚本（linux→bash，windows→PowerShell）。
func (d *NativeDeployer) RenderScript(node *DeployNode, desc *DeployDesc) (script string, err error)
// Deploy 渲染脚本 + 传文件 + 执行 + 健康检查。
func (d *NativeDeployer) Deploy(ctx context.Context, app *Application, node *DeployNode, exec RemoteExecutor, desc *DeployDesc) (DeployResult, error)
```

- `RenderScript` 内部按 `node.OSType` 分支：linux 渲染 bash（transfer→PutFile、run→原样、service→systemd unit + `systemctl`、healthcheck→原样）；windows 渲染 PowerShell（transfer→PutFile、run→原样、service→`sc create`/`Register-ScheduledTask`、healthcheck→原样）。
- `Deploy` 流程：①读 `deploy.yaml`（RepoDir）解析 desc ②RenderScript ③逐 transfer 步 `exec.PutFile` 产物 ④`exec.Run(script)` ⑤healthcheck ⑥通过→status=running。
- web 应用（app_kind=web）仍走现有 `Deployer.Build/Deploy`（Docker），不读 deploy.yaml。

### 5.4 关键约束

- 部署描述驱动不限类型：transfer/run/service/healthcheck 四类步骤组合出任意部署形态。
- web/Docker 链路零改动，NativeDeployer 是并存能力。
- `RenderScript` 纯函数（desc+node → 脚本字符串），可单测。
- 远端路径防逃逸：`target.dir` + 文件名校验（拒绝 `../`/绝对路径越界）。
- 产物来源：非 web 应用从 MinIO/本地产物取（`transfer.from` 支持产物目录 glob）。

## 6. 监督采集 + 看板

### 6.1 server_metric 表（迁移 000023 一并建）

```sql
CREATE TABLE IF NOT EXISTS appdeploy_server_metric (
    node_id     TEXT NOT NULL,
    captured_at TIMESTAMPTZ NOT NULL,
    cpu_percent REAL NOT NULL,
    mem_total   BIGINT NOT NULL,
    mem_used    BIGINT NOT NULL,
    disk_total  BIGINT NOT NULL,
    disk_used   BIGINT NOT NULL,
    load_avg    REAL,
    uptime      TEXT,
    app_count   INT NOT NULL DEFAULT 0,
    PRIMARY KEY (node_id, captured_at)
);
CREATE INDEX IF NOT EXISTS idx_metric_node_time ON appdeploy_server_metric(node_id, captured_at DESC);
```

### 6.2 ServerMonitor（`internal/appdeploy/monitor.go`）

```go
type ServerMonitor struct{
    nodeStore *NodeStore
    metricStore *MetricStore
    interval time.Duration  // 默认 60s
}
func (m *ServerMonitor) collectNode(ctx context.Context, n *DeployNode) (metric, error)
func (m *ServerMonitor) Start(ctx context.Context)  // 后台定期采集
func (m *ServerMonitor) CollectOnce(ctx context.Context, nodeID string) error  // 手动
```

- **Linux 采集**（SSH）：CPU=`top -bn1`；内存=`free -k`；磁盘=`df -k /`；负载=`cat /proc/loadavg`；uptime=`uptime -p`。
- **Windows 采集**（WinRM）：CPU=`Get-Counter '\Processor(_Total)\% Processor Time'`；内存=`Get-CimInstance Win32_OperatingSystem`；磁盘=`Get-Volume`；uptime=`LastBootUpTime`。
- 解析纯函数 `parseLinuxMetrics(stdout) → metric` / `parseWindowsMetrics(stdout) → metric`，可单测。

### 6.3 接口

```
GET  /deploy-nodes                       # 扩展返回字段(os/env/connect/latest_metric)
POST /deploy-nodes/:nid/collect          # 手动采集
GET  /deploy-nodes/:nid/metrics?since=&limit=  # 历史趋势
```

### 6.4 前端：服务器管理看板（`/servers`）

- 节点列表：卡片（名称/host/OS 图标/env 徽章/状态灯/CPU 条/内存条/磁盘条/应用数/最近采集）。
- 详情抽屉：历史趋势图（CPU/内存/磁盘折线，主题 token 配色）+ provision 日志 + 测试/搭建/手动采集按钮。
- 侧栏加「🖥 服务器管理」入口（NAV + tabs NAV_MAP 双注册）。
- 暗色适配（主题 token）。

### 6.5 关键约束

- 不装 agent：采集靠 ANP 主动 SSH/WinRM 跑命令。
- 采集失败（离线/凭证错）→ 不写 metric，节点 status 标 `degraded` + last_seen 不更新。
- CPU 解析跨 distro/Windows 差异，纯函数 + 测试兜底。
- 历史表定期清理 30 天前（留备注）。

## 7. dev/test/prod 分组 + 与现有部署链路关系

### 7.1 分组

- `DeployNode.Env`（dev/test/prod）。`node_local` 默认 `env=test`。
- 部署按环境过滤：test 应用只能选 `env=test` 节点，prod 应用选 `env=prod`。前端节点选择器按环境过滤。
- `/servers` 看板按 env 分组展示。

### 7.2 与现有部署链路

| 应用形态                      | 部署链路                                         | 节点                           |
| ----------------------------- | ------------------------------------------------ | ------------------------------ |
| web（Dockerfile）             | 现有 `Deployer.Build/Deploy`（docker build/run） | Linux（docker_tcp 或 SSH）     |
| 非 web 原生（带 deploy.yaml） | 新 `NativeDeployer`（渲染脚本 + SSH/WinRM）      | Linux（SSH）/ Windows（WinRM） |
| 非 web 产物下载               | 现有 `BuildArtifacts` + 下载                     | 不部署                         |

现有 `docker_tcp` 节点保持兼容零改动；新 SSH/WinRM 节点是增量。

## 8. 明确不含（边界）

- K8s 集群纳管（本板块是单机 docker/原生节点）
- 自动弹性扩缩容
- Windows 装 Docker（明确不要）
- 监督 agent（主动采集）
- 凭证加密存储（WinRM 密码/SSH 私钥本期明文，下期加密）
- 历史趋势预测/告警研判（板块07 运维中心职责，不重叠）
- 多节点负载均衡/高可用部署

## 9. 验收标准

1. 添加 Linux 节点（SSH 凭证）→ `provision` 装上 Docker → `status=ready` → 部署 web 应用到该节点 → 应用跑起来。
2. 添加 Windows 节点（WinRM 凭证）→ `provision` 验连通 → 带 `deploy.yaml` 的原生应用部署到 Win 节点 → 应用跑起来。
3. `/servers` 看板显示所有节点资源（CPU/内存/磁盘条）+ 状态 + env 徽章，定期自动刷新。
4. 节点按 dev/test/prod 分组；部署应用时节点选择器按环境过滤。
5. 现有 `.28 node_local` + docker_tcp 节点全链路不受影响（回归不破）。
6. `pnpm tsc` + `pnpm build` 通过；后端 `go build` + `go test ./internal/appdeploy/` 通过。

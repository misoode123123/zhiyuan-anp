## 1. 目标

导入项目后（或应用详情"重新分析"按钮）扫描仓库，产出**结构化部署分析事实**：语言/框架、构建方式、外部依赖、网络需求、形态猜测、与 ANP 默认模型的差异点。供：

- **编码适配（opencode）**：带着这份事实去改 config/Dockerfile；
- **后续项**：依赖注入读 `deps`、headless 读 `app_kind_guess`；
- **人工**：一眼看清"这应用要怎么部署、跟 ANP 模型差在哪"。

**原则**：规则提事实为主（确定性、可单测、零 token），不造重型引擎；不opencode改码（那是另一项）。

## 2. 范围

**做**：扫描**已 flatten 的**仓库根 → 结构化 `DeployAnalysis` → 落库；导入末尾自动触发 + 应用详情"重新分析"。

**不做**（其他项）：自动改码适配（opencode）、依赖供给/注入、host 网络门禁、多平台构建。

## 3. 分析信号（规则层）

| 维度                  | 信号                                                                                                                                                                                     | 判定                                                                 |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 语言/框架             | `go.mod`/`main.go` → Go；`package.json` → Node；`requirements.txt`/`pyproject.toml` → Python；`pom.xml`/`build.gradle` → Java                                                            | 给 `language` + `framework`(若能识别)                                |
| 构建                  | 有无 `Dockerfile`、有无 `docker-compose.yml` + 其 services 列表                                                                                                                          | `build.dockerfile/compose/compose_services`；都无→buildpack 兜底提示 |
| 外部依赖              | 扫配置文件（`*.yaml/*.yml/*.env/*.ini/*.conf/*.toml`）里的 `host:port`、`127.0.0.1/localhost`、依赖关键词（redis/milvus/postgres/mysql/mongo/kafka/es/minio…）                           | `deps[{kind,addr}]`                                                  |
| 网络                  | compose `network_mode: host` → host 需求；统计 `127.0.0.1` 引用数                                                                                                                        | `network.host_mode_required/reason`                                  |
| 端口                  | Dockerfile `EXPOSE` / compose `ports` / `internal_port`                                                                                                                                  | `ports.expose[]`                                                     |
| 形态 `app_kind_guess` | 有 HTTP 框架/`EXPOSE` → `web`；wecom/bot/worker/cron 关键词且无 HTTP → `headless`；`electron`/`tauri` → `desktop`；`miniprogram`/`app.json`(小程序) → `miniapp`；`cmd/`+cli 框架 → `cli` | 按 §11#1 默认的组件类型集                                            |
| 与 ANP 差异           | 规则比对：需 host 但 ANP 默认 bridge / 依赖非 PG 的服务 ANP 没给 / buildpack 易误判 / 客户端类型运行不在 ANP                                                                             | `mismatches[]` + `adapt_hints[]`                                     |

## 4. 输出 schema（`DeployAnalysis`，JSONB 落库）

```json
{
  "language": "go",
  "framework": "",
  "build": {
    "dockerfile": true,
    "compose": true,
    "compose_services": ["bot", "redis", "milvus", "postgres", "etcd", "minio"]
  },
  "app_kind_guess": "headless",
  "deps": [
    { "kind": "redis", "addr": "127.0.0.1:6379" },
    { "kind": "milvus", "addr": "127.0.0.1:19530" },
    { "kind": "postgres", "addr": "127.0.0.1:5432", "database": "yxt_wecom_bot" }
  ],
  "network": { "host_mode_required": true, "reason": "compose network_mode:host" },
  "ports": { "expose": [9090, 9091] },
  "mismatches": [
    "需 host 网络但 ANP 默认 bridge",
    "依赖 Redis/Milvus/PG 但 ANP 仅供给 PG",
    "buildpack 易误判 static、实为 Go 后端"
  ],
  "adapt_hints": [
    "Redis 改指部署机可达地址",
    "需供给/链接 Milvus 与 PG(yxt_wecom_bot)",
    "建议按 host 网络或改 config 走 env"
  ]
}
```

## 5. 数据模型

新表 `appdeploy_deploy_analysis`：`(app_id, analysis JSONB, analyzed_at)`，可多版本/历史。或先加 JSONB 列到 `appdeploy_application`（MVP 单版本）。**倾向新表**（可追溯）。

## 6. 集成点

- 导入流程末尾（`ImportFromZip/Dir/Git` 之后、状态置 `registered` 时）自动调 Analyzer，结果落库。
- 应用详情加"重新分析"端点 + 按钮。
- 不阻塞导入（分析失败只记 `last_error`，不影响导入成功）。

## 7. 测试

Analyzer 为纯函数（输入 repoDir → `DeployAnalysis`），表驱动单测；**客服机器人 repo 作黄金用例**：须识别出 Go + compose + host 网络 + Redis/Milvus/PG + mismatches。另加：扁平 web 仓、纯 Node、空仓的 case。扫描加超时 + 路径穿越防护（复用 `ReadRepoFile` 范式）。

## 8. 假设的决议（按 PRD §9 推荐 default，可改）

- **§9#1 组件粒度**：`app_kind_guess` 用 web/api/headless/data/middleware（+ desktop/miniapp/cli 等客户端类型）。
- §9#2 供给默认 `bind-existing`、#3 host 复用变更闸门、#4 产物态先通用、#5 小程序远期、#6 shared 提供（已定）——均不在本项范围内，仅记录。

## 9. 非目标

不做：opencode 自动改码、供给/注入依赖服务、开 host 网络、多平台构建。这些是后续独立项。

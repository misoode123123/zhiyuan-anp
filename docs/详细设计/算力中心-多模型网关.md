# 算力中心 · 多平台多模型统一网关（详细设计）

> 将算力中心从"用量记录器"升级为**模型网关**：统一管理多供应商多模型、智能路由、成本核算。
> agent-runtime + opencode 都经它调模型。企业只投算力（加 provider），平台智能路由。

---

## 1. 背景与目标

### 现状问题

- 模型配置散落：智谱 key 在 system_config / .env / opencode.json 三处，改一处忘一处；
- 只支持单一供应商（智谱），无法接 OpenAI/Claude/Ollama/vLLM；
- 无路由（所有任务用同模型，不能"规格用快的、编码用强的"）；
- 无成本核算（只记 token 数，不算钱）；
- 无供应商/模型管理界面（加模型要改文件）。

### 目标

| 目标     | 说明                                                                          |
| -------- | ----------------------------------------------------------------------------- |
| 多供应商 | 一个界面管理智谱/OpenAI/Claude/Ollama/vLLM 等，各自 base_url + key            |
| 多模型   | 每 supplier 下多个模型，标注能力(vision/code/reasoning) + 成本(每千token单价) |
| 智能路由 | 按任务类型(spec/code/test/review)自动选模型 + fallback                        |
| 统一网关 | 暴露统一 /v1/chat（OpenAI-compatible），agent-runtime/opencode 经它调用       |
| 成本核算 | 每次调用算钱，按 provider/model/项目/时间看板                                 |
| 配额     | 按项目/部门设月度预算，超限告警                                               |

## 2. 数据模型

### 2.1 provider（供应商）

```sql
CREATE TABLE compute_provider (
  id          TEXT PRIMARY KEY,
  name        TEXT NOT NULL,              -- 智谱/OpenAI/Claude/Ollama/vLLM
  type        TEXT NOT NULL DEFAULT 'api', -- api / local
  base_url    TEXT NOT NULL,              -- https://open.bigmodel.cn/api/paas/v4
  api_key     TEXT,                       -- 加密存（local 无）
  enabled     BOOLEAN NOT NULL DEFAULT TRUE,
  config      JSONB,                      -- supplier 特定配置（coding_endpoint 等）
  description TEXT,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### 2.2 model（模型）

```sql
CREATE TABLE compute_model (
  id            TEXT PRIMARY KEY,
  provider_id   TEXT NOT NULL REFERENCES compute_provider(id),
  name          TEXT NOT NULL,            -- glm-5.1 / gpt-4o / claude-sonnet-4-5
  display_name  TEXT,                     -- GLM-5.1
  modality      TEXT NOT NULL DEFAULT 'text', -- text / vision / voice / code
  context_window INTEGER,                 -- 204800
  max_output    INTEGER,                  -- 131072
  cost_input    REAL NOT NULL DEFAULT 0,  -- 每千 token 输入单价（元）
  cost_output   REAL NOT NULL DEFAULT 0,  -- 每千 token 输出单价（元）
  capabilities  JSONB,                    -- ["reasoning","vision","function_calling"]
  enabled       BOOLEAN NOT NULL DEFAULT TRUE,
  created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE(provider_id, name)
);
```

### 2.3 model_route（路由策略）

```sql
CREATE TABLE compute_route (
  id                TEXT PRIMARY KEY,
  task_type         TEXT NOT NULL UNIQUE, -- spec / code / test / review / chat / general
  primary_model_id  TEXT NOT NULL REFERENCES compute_model(id),
  fallback_model_id TEXT REFERENCES compute_model(id),
  priority          INTEGER NOT NULL DEFAULT 0,
  enabled           BOOLEAN NOT NULL DEFAULT TRUE,
  updated_at        TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### 2.4 usage_record（扩展现有）

```sql
ALTER TABLE usage_record
  ADD COLUMN provider_id TEXT,
  ADD COLUMN model_id    TEXT,
  ADD COLUMN cost        REAL NOT NULL DEFAULT 0;  -- 本次调用成本（元）
```

## 3. 核心能力

### 3.1 供应商管理（Provider CRUD）

| 操作 | API                                     | 说明                              |
| ---- | --------------------------------------- | --------------------------------- |
| 列表 | GET /api/v1/compute/providers           | 全部供应商                        |
| 创建 | POST /api/v1/compute/providers          | name/type/base_url/api_key        |
| 更新 | PUT /api/v1/compute/providers/:id       | 改 base_url/key/enabled           |
| 删除 | DELETE /api/v1/compute/providers/:id    | 级联删 model                      |
| 测试 | POST /api/v1/compute/providers/:id/test | ping 供应商（发一条 hi 测试连通） |

### 3.2 模型管理（Model CRUD）

| 操作 | API                                     | 说明                            |
| ---- | --------------------------------------- | ------------------------------- |
| 列表 | GET /api/v1/compute/models?provider_id= | 按 supplier 筛选                |
| 创建 | POST /api/v1/compute/models             | name/modality/cost/capabilities |
| 更新 | PUT /api/v1/compute/models/:id          | 改成本/能力/启用                |
| 删除 | DELETE /api/v1/compute/models/:id       |                                 |

### 3.3 路由策略（Route CRUD）

| 操作 | API                                   | 说明                                  |
| ---- | ------------------------------------- | ------------------------------------- |
| 列表 | GET /api/v1/compute/routes            | 全部路由                              |
| 设置 | PUT /api/v1/compute/routes/:task_type | {primary_model_id, fallback_model_id} |

默认路由（seed）：

```
spec    → glm-4-flash（快，便宜）
code    → glm-5.1（强，coding plan）
test    → glm-4-flash（快）
review  → glm-4.6（中等）
chat    → glm-4-flash（快）
general → glm-5.1
```

### 3.4 统一调用（网关）

```
POST /api/v1/compute/chat
Body: { task_type: "code", messages: [...], project_space_id: "ps_xxx" }
→ 查 route(task_type) → 取 primary_model → 查 model 的 provider → 转发到 provider.base_url
→ 失败 → fallback_model → 记 usage(provider_id, model_id, tokens, cost)
```

### 3.5 成本核算

- model 表存 `cost_input` / `cost_output`（每千 token 单价）；
- 每次调用后：`cost = prompt_tokens/1000 * cost_input + completion_tokens/1000 * cost_output`；
- 记 `usage_record(provider_id, model_id, cost)`；
- 看板：按 provider/model/项目/时间 聚合（已有 Stats 扩展）。

## 4. 智能路由策略

```
任务来了(task_type=code)
    │
    ▼
查 route(code) → primary=glm-5.1, fallback=glm-4.6
    │
    ▼
glm-5.1 调用 → 成功？→ 记账返回
    │ 失败/超时
    ▼
fallback glm-4.6 → 成功？→ 记账返回
    │ 失败
    ▼
返回错误（无可用模型）
```

**进阶路由**（P2）：

- 按预算选模型（预算紧→便宜模型）；
- 按延迟选（实时对话→快模型）；
- 按能力选（需要 vision→vision 模型）；
- 负载均衡（多 provider 同级模型轮询）。

## 7. 与现有模块集成

### agent-runtime（Python 侧）

- 当前：gateway.py 直接持 zhipuai SDK + key 调智谱；
- 改为：gateway.py 调 **算力中心 `/api/v1/compute/chat`**（传 task_type），由算力中心路由+转发；
- 好处：Python 侧不再持 key，加新供应商只改算力中心（DB），不动 Python。

### opencode（编码引擎）

- 当前：opencode.json 固定 zai-coding provider；
- 改为：算力中心生成 opencode.json（从 DB 读 provider/model，动态输出 coding provider 配置）；
- 或：opencode 也调算力中心 `/compute/chat`（需 opencode 支持 custom endpoint——已支持 openai-compatible）。

### system_config（配置中心）

- `zhipuai_api_key` / `default_model` 等迁到 compute_provider/compute_model 表；
- system_config 只留平台运行配置（端口/DB 等），模型配置全在算力中心。

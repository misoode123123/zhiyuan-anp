## 1. 做了什么

给 appdeploy 应用加 `network_mode`（bridge 默认 / host 需授权），host 模式容器以 `--network host` 运行（共享宿主网络命名空间，直接绑宿主端口、直达 host-LAN）；双 RBAC 角色门禁（op `app.net.host` = gatekeeper/admin）：

- **set-time 门禁**：`PUT /project-spaces/:id/apps/:aid/network-mode`（`PutNetworkMode` handler）。改 network_mode（双向）需 `app.net.host`。routeOps 登记（静态 op → AutoRequire 注 roles + 强制）；handler 内联检查留作 defense-in-depth。
- **deploy-time 门禁**：`Deploy`/`Promote`/`DeployCommit` 三入口，`a.NetworkMode=="host" && !auth.Allowed("app.net.host", roles)` → 403（同步，在 `buildAndDeploy` goroutine 前）。
- **deployer host 分支**：`--network host` flag 提到 app_kind 分支前（正交，含 headless）；web/service host 模式跳 `-p`+端口分配、`port=a.InternalPort`、`ins.HostPort=port`、`ins.URL=http://<urlHost>:<port>`。**复用既有 `routeWriter.UpsertRoute(..., ins.HostPort)` + URL 逻辑零改动**（ins.HostPort 语义复用为「host 命名空间可达端口」）。
- **前端**：应用管理页 `NetworkModeSection` 选择器（范式照 `DepsSection`），改选即 PUT；403 toast（不前置置灰——见 §4 偏离）。
- **migration `000034`**：`appdeploy_application.network_mode TEXT NOT NULL DEFAULT 'bridge'`（幂等 up/down）。

**零新表、零新 FK、零新索引、零新依赖**（1 迁移 + 1 列 + 1 op + set/deploy 两道 gate + deployer 1 分支 + UI 1 选择器）。

## 2. 关键决策

1. **审批机制 = 角色门禁（PRD §9.3 → A）**：与 prod 部署同款「角色即审批」（gatekeeper/admin），无独立工单。rejected 复用变更闸门（change_request 字段代码专用，host 是运行时策略，语义勉强）/ 独立审批表（YAGNI 偏重）。
2. **`network_mode` app 级标量列**：非 per-env、非 JSONB（全标量表加一列最简）。
3. **`ins.HostPort` 复用为 host 可达端口**：host 模式无 `-p` 但 app 绑 internalPort 于宿主 → `ins.HostPort=internalPort` → 下游 appgw 路由 + URL 零改动。
4. **专用 `PUT /network-mode` 端点**：单职责 gate 干净。
5. **set-time + deploy-time 双 gate**：set-time 防 dev 私开 host；deploy-time 防 dev 部署他人开的 host 应用。

## 5. 教训（重点）

1. **新加 gated handler 必须同步登记 routeOps**：`AutoRequire` 是生产唯一向 gin context 注入 roles 的地方。route 未登记 routeOps → `RouteOp` 返 "" → 中间件 `c.Next()` 直接返回**不 `c.Set("roles",…)`** → handler `rolesFromCtx` 返 nil → `Allowed(op, nil)`=false → **全员 403 含 admin**。本例 PutNetworkMode 漏登记，set-time 门禁生产全瘫。
2. **测试中间件绕过 AutoRequire 会掩盖集成缺口**：`newRouterWith`/`newRouterWithRoles` 用测试中间件直接 `c.Set("roles",…)`，T3 的 4 个测试全过，却没发现 routeOps 缺登记——因为根本没走 AutoRequire。**gated handler 须有「routeOps 登记」的直测**（本例加 `TestRouteOp_NetworkModeRegistered` 断言 `RouteOp(...)==op`）。final whole-branch review（跨任务、看生产集成）才抓到，task-scoped review 看不到。
3. **静态 op 用 routeOps 真实 op、动态 op 用占位**：env 敏感（deploy.test/prod）用占位 `app.deploy._`+handler 二次鉴权；静态 op（host 网络与 env 无关）直接登记真实 op `app.net.host`，AutoRequire 强制，handler 检查作 defense-in-depth。
4. **deployer host flag 与 app_kind 正交**：host flag 须在 app_kind 分支前统一加，否则 headless 分支先 return 会吞掉 host（headless+host 拿不到 `--network host`）。
5. **Promote 的 `a` 是 if-scope**：原 `if a,_:=Get(); a==nil{}` 把 `a` 限在 if 语句内，gate 读 `a.NetworkMode` 编译不过——提升到函数 scope（保 404 语义）。
6. **Windows bash 与 Windows python 路径不一致**：git-bash `/tmp/x` ≠ Windows python 的 `C:\tmp\x`，python `open('/tmp/x')` FileNotFoundError。e2e 提取 ASCII token 用 git-bash `sed`，避免 python；含中文响应用 -o file + 注意编码。

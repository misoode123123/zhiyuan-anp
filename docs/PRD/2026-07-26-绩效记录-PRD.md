# PRD/设计：绩效记录（按人统计开发产出 + 开发者↔工具互动聊天）

| 版本 | 日期       | 作者     | 状态   |
| ---- | ---------- | -------- | ------ |
| v1.0 | 2026-07-26 | ANP 团队 | 待评审 |

> 现状摸底见本轮对话「②绩效记录 摸底」。本 spec 是「工作台三需求」分三份中的**第 2 份**（顺序 ①部署权限 → ③多AI工具 → ②绩效记录），①③ 已闭环并部署 .28 验证通过。

## 1. 背景与目标

**现状**：平台零绩效统计能力。根因——

- 开发工作流核心表 `code_task`/`change_request`/`conversation` 都缺 `user_id`，无法按人聚合；`release_record` 无作者。
- `operation_log.actor_id` 列本意存 user id（迁移注释明示），但写入方传的是 username（`CtxUserID` 存的是 name）。
- `codews` 编码工作台**纯内存**，dev↔AI 工具的互动聊天平台侧完全没持久化。
- 考勤模块（attendance）走"提交→审批"重 CRUD，与本平台方向不符，删除。

**目标**：

1. 按人（开发者）**自动统计**开发产出，只读看板，零手工录入。
2. **重点**：完整呈现开发者与编码工具（opencode/claude/codex）的**互动聊天记录**——三工具都拿到完整对话内容（读工具自家的磁盘 transcript，**非** ttyd 抓屏）。
3. 可见范围：admin 看本空间全员，本人看自己。
4. 顺手删除考勤模块。

**关键约束（决策已定）**：自动统计看板（非人工评价）；admin/本人两级可见；归属靠给工作表补 `user_id`（非中心事件表）；互动聊天读工具原生 transcript 文件、DB 只存会话级计数。

## 3. 设计

### 3.1 归属修复（绩效前提）

- **中间件**：`auth.ValidToken`（`user.go:116`）扩为返回 `(name, userID)`（`auth_session` 本就有 user_id）；`AuthUser`（`middleware.go:49`）除 `CtxUserID`=name 外，多设 `CtxUserDBID`=user.id。老 key 不动，零回归。
- **三表加列**（新迁移 `000018`）：`code_task`/`change_request`/`conversation` 各加可空 `user_id TEXT`。写入处补字段：`codetask/store.go:20`、`conversation/store.go:25`、`change/store.go:38` 的 INSERT 加 user_id（从 ctx 取 `CtxUserDBID`，handler 透传）+ 各 model 加 UserID 字段。
- **release**：不加列，聚合时 `release_record JOIN change_request ON change_id` 取 user_id。
- **operation_log**：审计中间件（`main.go:212`）改取 `CtxUserDBID` 喂 `actor_id`（列本就在，顺带修正）。
- **历史存量**：user_id 为 NULL 的行统计时进"未归属"桶并显式标注；不强行回填（username→id 模糊匹配不靠谱），不静默丢弃。

### 3.2 开发者↔工具互动聊天抓取（重点）

新增 `codews/transcript.go` 的 `TranscriptReader` 接口（与现有 `Tool` 接口平行）：

```go
type TranscriptMeta struct { SessionID, Tool, Cwd string; UpdatedAt time.Time; PromptCount int }
type TranscriptMsg struct { Role, Content string; CreatedAt time.Time }

type TranscriptReader interface {
    Sessions(repoDir string) ([]TranscriptMeta, error)            // 该 repo 的会话列表（最近在前）
    Messages(repoDir, sessionID string) ([]TranscriptMsg, error)  // 单会话归一化消息
}
```

三个实现（按工具自家文件解析、归一化为同一结构）：

- `claudeReader`：扫 `$CLAUDE_HOME/projects/*/*.jsonl`，**按记录内 `cwd` 字段匹配 repoDir**（不靠目录名编码，规避中文/特殊字符编码差异），取 `type=user/assistant` 行；`content` 兼容 string 与 `[{type:text,text}]` 数组两种形态。
- `codexReader`：扫 `$CODEX_HOME/sessions/**/*.jsonl`，按记录 cwd 过滤。
- `opencodeReader`：复用现有 `SessionMessages`（HTTP API）+ 磁盘兜底。

**定位策略**：ttyd 不回传 sessionId，绕开——用 repoDir + 时间近邻匹配 transcript；`codews_session` 表存 repoDir 即可，详情时按 repoDir 解析。

### 3.3 codews 会话持久化

新表 `codews_session`（迁移 `000018`）：

```
id, project_space_id, app_id, user_id, tool, repo_dir, port,
session_id(可空, opencode 有/claude·codex 按 repoDir 解析),
started_at, ended_at(可空), prompt_count default 0, message_count default 0, created_at
```

- `Manager.Ensure`（`manager.go:106`）启动成功后插一行；进程退出回调（`:152`）更新 `ended_at` + 调 TranscriptReader 回填 `prompt_count`/`message_count`。
- 这样绩效聚合"会话数/时长/prompt 数/工具分布"走 DB（快），**完整聊天内容走 TranscriptReader 按需读**（省存储、免同步漂移）。
- **活跃会话计数**：prompt/message 计数在会话结束时回填；进行中会话计数为 0。若需实时，详情接口按需即时解析 transcript 即得（不依赖回填）。

### 3.4 绩效聚合模块

新包 `internal/performance`：

- `Store.Summary(ctx, psID, userID, from, to) Profile`：跨表 `GROUP BY user_id` 聚合（仿 `ops/store.go:164` countByStatus 范式，但按人）。
- `Store.Members(ctx, psID, from, to) []Profile`：admin 全员排行榜。
- 只读、按需聚合，MVP 不物化（YAGNI；平台数据量小）。

**指标**（`[from,to]` × project_space）：

- 🟢 **编码工作台互动（置顶）**：会话数、活跃时长、prompt 数、工具分布；可下钻看完整聊天记录。
- 需求：认领数、已完成数。
- 编码任务：完成数 / 失败数。
- 变更：提交数、通过数、驳回数。
- 发布：发布次数。
- 需求梳理：发起 conversation 数。

### 3.5 API（project_space 隔离，挂 v1，走 AutoRequire）

- `GET /performance/me?from=&to=` — 本人（任意登录用户，自校验 user_id=自己）。
- `GET /performance/members?from=&to=` — admin：全员排行榜。
- `GET /performance/members/:user_id` — admin：某人明细。
- `GET /performance/sessions/:session_id/messages` — 看某次互动完整聊天（TranscriptReader 按需读）。
- `members/*`、`sessions/*` 守卫 admin 角色（RBAC role=admin）；`me` 仅自校验。
- `from`/`to` 为可选时间窗（`YYYY-MM-DD`），缺省=当月 1 日至今。

### 3.6 前端

- 新页 `app/performance/page.tsx`：本人看板（指标卡 + 互动区置顶 + 趋势）；admin 视图加成员列表，可下钻到某人 + 某次会话聊天记录。
- 图表实现时调 dataviz 技能。
- 删 `app/attendance/page.tsx` 及导航项。

后端删 `internal/attendance/` 全包、`main.go:29/188/240`；迁移 `000018` 同步 `DROP TABLE attendance_record`（干净 drop）；前端删页 + `lib/api-types.ts` 去 Attendance；swagger 重生成；`standards_seed` 去考勤标准。

## 6. 风险与边界

- **transcript 解析稳定性**：claude/codex 的 JSONL schema 随 CLI 版本可能变 → 解析容错（未知字段忽略；content string/数组双兼容）；解析失败时会话级计数仍可用，仅聊天详情降级提示。
- **codex volume**：未挂则 codex transcript 容器重启丢失；AC5 依赖补挂 `~/.codex`。
- **cwd 匹配**：worktree 路径（`<repo>/.worktrees/dev-<user>`）与 transcript 内 cwd 一致（`ensureWorktree` 固定该路径），匹配可靠。
- **归属历史断点**：cutover 前的行无 user_id，明确进"未归属"桶，统计口径标注"自上线日起完整"。
- **大 transcript**：按需读不入库；详情接口加分页/截断，避免单次返回过大。
- **跨节点**：MVP 单容器（工具与 backend 同机）；未来分布式部署需共享 transcript 卷或改入库——标 P2。

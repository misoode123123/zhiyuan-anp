# 导入已有项目（方案 2：纳入 AI 开发）PRD/设计

日期：2026-07-27
范围：把**已有代码的项目**（远程 git 仓库 / 本地文件目录）导入 ANP 托管仓库，落地为一个 `managed` Application，后续走 ANP 全流程（AI 编码 / 审批 / 部署 / 提新需求）。**向前看，不迁历史需求。**

## 1. 背景

总方案规划三类项目接入形态，当前实现进度：

| 形态            | 含义                                             | 当前状态                                                          |
| --------------- | ------------------------------------------------ | ----------------------------------------------------------------- |
| A. AI 新研发    | 全新应用，平台建仓 → AI 编码 → 部署              | ✅ 已实现（`appdeploy.Create` → `EnsureRepo` → AI 编码 → Deploy） |
| B. 企业存量系统 | ① 仅注册+入口+探活 / **② 纳入代码** / ③ 接管需求 | ① 已实现（external 轻接入）、**② 本任务**、③ 留后续               |
| C. 外部 SaaS    | 钉钉/飞书 API 集成                               | 未做                                                              |

**现状缺口**（后端探索确认）：`appdeploy` 只会 `EnsureRepo`（`repo.go:27` = `git init` + 模板 README/docs），**无 `git clone`、无目录复制、无 zip 上传**。要把已有代码搬进托管仓 `/data/repos/<name>`，这个能力是完全空白的——本任务补它。

**用户已确认的边界**：

- 方案 2（向前看）：不迁历史需求/变更/发布记录，只从"今天起"的新需求走 ANP。
- 双来源：远程 git 仓库（含私有，需认证）+ 本地文件目录（**本机上传 zip** 与 **ANP 服务器已有目录** 两种都要）。
- 落地形态：作为**当前项目空间下一个 `Application`**（不造 `Project` L2 空壳——代码探索确认它无任何子表引用）。

## 5. 导入实现（`appdeploy/repo.go`）

在 `EnsureRepo`（`repo.go:27`）旁新增三个导入函数。**导入分支不调 `EnsureRepo` 的模板逻辑**（不覆盖已有代码/文档），只确保目标是个可用 git 仓。

### 5.1 `ImportFromGit`（远程仓库，含私有）

```go
// ImportFromGit 把远程仓库 clone 到托管仓 ManagedRepoDir(name)。
// auth: HTTPS 时注入 http.extraHeader（推荐，不污染 URL）；SSH 时留空（走部署机 ~/.ssh + known_hosts）。
// clone 在 ManagedRepoBase 下执行（runGit 的 dir=父目录），目标目录=sanitizeName(name)。
func ImportFromGit(ctx context.Context, name, gitURL, authToken string) (string, error) {
    target := ManagedRepoDir(name)            // /data/repos/<name>
    if _, err := os.Stat(target); err == nil {
        return "", fmt.Errorf("目标目录已存在: %s（应用名冲突）", target)
    }
    args := []string{"clone", "--progress", gitURL, target}
    // 私有 HTTPS：用 extraHeader 注入 token（不落 URL 历史，不污染 git config）
    dir := ManagedRepoBase
    if authToken != "" && !strings.HasPrefix(gitURL, "git@") {
        // 通过 -c 临时注入，不写 config
        args = append([]string{"-c", "http.extraHeader=Authorization: Bearer " + authToken}, args...)
    }
    if _, err := runGit(ctx, dir, args...); err != nil {
        _ = os.RemoveAll(target) // 清理半成品
        return "", fmt.Errorf("git clone 失败: %w（检查 URL/认证/网络）", err)
    }
    // 设默认身份（编码提交用），保留 origin 不动（不自动同步）
    _, _ = runGit(ctx, target, "config", "user.email", "anp@platform")
    _, _ = runGit(ctx, target, "config", "user.name", "ANP Platform")
    return target, nil
}
```

- **认证策略**：
  - HTTPS 私有仓：`git -c http.extraHeader="Authorization: Bearer <token>" clone ...`（GitLab/GitHub PAT 通用，不落 config/URL）。
  - SSH 私有仓：URL 形如 `git@host:group/repo.git`，依赖部署机（.28）已配置的 SSH key 与 `known_hosts`，无需额外凭证。
  - **token 不落库**：handler 收到 token → 传给 `ImportFromGit` 用完即弃，不写 DB；日志对 URL/token 脱敏（见 §8）。
- **保留 origin**：clone 自带 origin，便于将来手动 `git pull` 同步上游；**不自动同步**。

### 5.2 `ImportFromZip`（本机目录上传）

```go
// ImportFromZip 把上传的 zip 解压到托管仓 ManagedRepoDir(name)。
// reader=multipart 上传的 zip；校验解压总大小/文件数上限、防 zip slip 路径穿越、防 zip bomb。
// 若 zip 含 .git 则保留历史；否则 git init + 初始提交。
func ImportFromZip(ctx context.Context, name string, r io.ReaderAt, size int64) (string, error) {
    target := ManagedRepoDir(name)
    if _, err := os.Stat(target); err == nil {
        return "", fmt.Errorf("目标目录已存在: %s", target)
    }
    if size > MaxZipSize { // 500MB
        return "", fmt.Errorf("zip 过大: %d > %d", size, MaxZipSize)
    }
    zr, err := zip.NewReader(r, size)
    if err != nil { return "", fmt.Errorf("zip 读取失败: %w", err) }
    if err := os.MkdirAll(target, 0755); err != nil { return "", err }

    var totalSize int64; var fileCount int
    cleanRoot := filepath.Clean(target)
    for _, f := range zr.File {
        if fileCount++; fileCount > MaxZipFiles { // 10000
            _ = os.RemoveAll(target); return "", fmt.Errorf("zip 文件数超限")
        }
        // 防 zip slip：解压目标必须在 target 之下
        dest := filepath.Clean(filepath.Join(target, f.Name))
        if !strings.HasPrefix(dest, cleanRoot+string(os.PathSeparator)) && dest != cleanRoot {
            _ = os.RemoveAll(target); return "", fmt.Errorf("zip slip 非法路径: %s", f.Name)
        }
        if f.FileInfo().IsDir() { os.MkdirAll(dest, 0755); continue }
        if totalSize += int64(f.UncompressedSize64); totalSize > MaxZipSize {
            _ = os.RemoveAll(target); return "", fmt.Errorf("zip 解压体积超限(bomb)")
        }
        // 拷贝文件内容（略，标准 archive/zip 解压）
    }
    // 若无 .git → git init + 初始提交（同 EnsureRepo 的身份设置，但不写模板文件）
    if _, err := os.Stat(filepath.Join(target, ".git")); err != nil {
        _ = runGit(ctx, target, "init", "-q")
        _ = runGit(ctx, target, "config", "user.email", "anp@platform")
        _ = runGit(ctx, target, "config", "user.name", "ANP Platform")
        _, _ = runGit(ctx, target, "add", "-A")
        _, _ = runGit(ctx, target, "commit", "-q", "-m", "import: 初始导入")
    }
    return target, nil
}
```

常量：`MaxZipSize = 500 * 1024 * 1024`、`MaxZipFiles = 10000`（可配置）。

### 5.3 `ImportFromDir`（ANP 服务器已有目录）

```go
// ImportFromDir 把服务器上的已有目录复制到托管仓。
// srcPath 必须在白名单根目录（AllowedDirRoots）下，防 ../ 穿越（参照 ReadRepoFile 的 HasPrefix 范式）。
// 若源含 .git 则 clone 本地路径（保留历史）；否则 cp -r 复制 + git init。
func ImportFromDir(ctx context.Context, name, srcPath string) (string, error) {
    cleanSrc := filepath.Clean(srcPath)
    if !isUnderAllowedRoot(cleanSrc) { // 白名单 + 防 ../ 穿越
        return "", fmt.Errorf("目录不在允许的根目录下: %s", srcPath)
    }
    if _, err := os.Stat(cleanSrc); err != nil {
        return "", fmt.Errorf("源目录不存在: %s", srcPath)
    }
    target := ManagedRepoDir(name)
    if _, err := os.Stat(target); err == nil {
        return "", fmt.Errorf("目标目录已存在: %s", target)
    }
    if _, err := os.Stat(filepath.Join(cleanSrc, ".git")); err == nil {
        // 源是 git 仓：本地 clone（保留历史，不复制 .git/objects 引用）
        _, err := runGit(ctx, ManagedRepoBase, "clone", cleanSrc, target)
        if err != nil { _ = os.RemoveAll(target); return "", err }
    } else {
        // 纯目录：cp -r 复制
        if err := exec.CommandContext(ctx, "cp", "-r", cleanSrc, target).Run(); err != nil {
            return "", err
        }
        _ = runGit(ctx, target, "init", "-q")
        _ = runGit(ctx, target, "config", "user.email", "anp@platform")
        _ = runGit(ctx, target, "config", "user.name", "ANP Platform")
        _, _ = runGit(ctx, target, "add", "-A")
        _, _ = runGit(ctx, target, "commit", "-q", "-m", "import: 初始导入")
    }
    return target, nil
}

// AllowedDirRoots 白名单根目录（配置项，默认 ["/data/", "/opt/legacy/"]）。
var AllowedDirRoots = []string{"/data/", "/opt/legacy/"}
func isUnderAllowedRoot(p string) bool {
    for _, root := range AllowedDirRoots {
        if strings.HasPrefix(p, root) { return true }
    }
    return false
}
```

## 6. 导入端点与异步流程（`appdeploy/handler.go`）

### 6.1 请求体

```go
type importBody struct {
    Source       string `json:"source" binding:"required,oneof=git dir"` // git=远程仓库 dir=服务器目录(zip 走 upload 端点)
    Name         string `json:"name" binding:"required"`                  // 应用名（过 validateAppName）

    // git 来源

    AuthToken string `json:"auth_token"` // 私有 HTTPS 仓的 token（不落库）；SSH 仓留空

```

> zip 上传走单独 multipart 端点（§6.3），先上传 → 后端拿 `name` 直接异步解压导入。

### 6.2 异步流程（`POST /project-spaces/:id/apps/import`）

```
1. bind + validateAppName + 配额 CheckApps（超限 409，不建任何记录）
2. 预检应用名唯一（store 同空间 name 唯一约束；冲突 409 提示改名）
3. git 来源：校验 git_url 合法（url.Parse，scheme http/https 或 ssh git@）；dir 来源：校验 server_path 在白名单下
4. 创建 Application 占位：status=importing, deploy_mode=managed, import_source/import_ref 落库, repo_dir=ManagedRepoDir(name)
   （占位即占用 name，保证后续异步期间不会被同名抢占）
5. go 异步执行（传 appID/psID 与导入参数；token 仅在闭包内使用，不落库）：
   a. store.UpdateImportProgress(status=importing, "正在克隆仓库/复制目录...")
   b. 调对应 ImportFromGit / ImportFromDir / ImportFromZip → 拿到 repoDir
   c. 成功 → store.UpdateImportDone(repoDir)（status=registered, imported_at=now, 清 last_error）
      → 供给独立库（provisioner.Provision，失败写 last_error 不阻塞）
   d. 失败 → store.UpdateImportProgress(status=failed, err) + 清理半成品目录（os.RemoveAll(ManagedRepoDir(name))）
6. 同步返回 201 + Application（status=importing），前端轮询 GET /apps/:aid 看 status + last_error 进度
```

- **进度载体**：复用 `status`（importing/registered/failed）+ `last_error`（写进度文本/错误）。不新增列。
- **异步实现**：MVP 用 goroutine（同进程）；局限见 §13（进程重启中断）。前端轮询已有 `GetApp`。

### 6.3 zip 上传端点（`POST /project-spaces/:id/apps/import/upload`，multipart）

```go
// @Router /project-spaces/{id}/apps/import/upload [post]
// 接收 multipart 文件字段 "file"（zip）+ 表单 "name"（应用名）+ 可选 "internal_port"。
// 设 r.MaxMultipartMemory = 32MB（超过写临时文件）；整体大小由 MaxZipSize=500MB 限制。
func (h *Handler) ImportUpload(c *gin.Context) {
    name := strings.TrimSpace(c.PostForm("name"))
    if msg := validateAppName(name); msg != "" { httpx.Err(c, 400, 40001, msg); return }
    if h.quota != nil { if err := h.quota.CheckApps(...); err != nil { httpx.Err(c, 409, 40950, ...); return } }
    fh, err := c.FormFile("file")
    if err != nil { httpx.Err(c, 400, 40001, "未收到 zip 文件"); return }
    if fh.Size > MaxZipSize { httpx.Err(c, 400, 40001, "zip 超过 500MB 限制"); return }
    // 创建占位 Application（status=importing, import_source=dir, import_ref=fh.Filename）→ go 异步 ImportFromZip
    // 同步返回 201 + Application（importing）
}
```

## 8. 安全

| 风险                 | 措施                                                                                                                                                      |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 私有仓库 token 泄露  | handler 收 token → 仅传导入函数闭包 → 用完即弃，**不落 DB**；日志对 `git_url`/`auth_token` 脱敏（替换为 `***`）                                           |
| 服务器目录越权       | `ServerPath` 必须在 `AllowedDirRoots`（默认 `/data/`、`/opt/legacy/`）下；`filepath.Clean` + `HasPrefix` 防 `../` 穿越（参照 `repo.go:196 ReadRepoFile`） |
| zip slip（路径穿越） | 每个解压 entry 校验 `filepath.Join` 后仍在 target 根下                                                                                                    |
| zip bomb（解压爆炸） | `MaxZipSize=500MB` + `MaxZipFiles=10000`，累计解压体积超限即中止清理                                                                                      |
| 权限                 | 导入走现有 RBAC（developer+ 可创建应用），同 `appdeploy.Create`                                                                                           |
| 配额                 | 导入建 Application 前过 `quota.CheckApps`（超限 409）                                                                                                     |
| 目标目录冲突         | `ManagedRepoDir(name)` 已存在则拒绝（防覆盖既有托管仓）                                                                                                   |

## 9. 错误处理与回滚

- **原子性**：任何导入步骤失败 → `os.RemoveAll(ManagedRepoDir(name))` 清理半成品目录 + Application 置 `status=failed` + `last_error` 写可读错误。**不留脏目录、不留 importing 僵尸记录**（失败即终态，可删除重试）。
- **应用名冲突**：同空间 `name` 唯一约束 → 预检 409 提示改名（不先 clone 浪费）。
- **远程仓库错误**：URL 非法 / 认证失败 / 仓库不存在 / 网络超时 → `git clone` 报错透传（脱敏）。
- **导入超时**：异步不阻塞 HTTP；大仓库耗时长，前端持续轮询进度；可加 `git clone --progress` 解析进度（可选增强）。
- **进程重启**：goroutine 中断，Application 卡 `importing`（局限，§13）→ 提供手动"标记失败/重试"入口。

## 13. 顾虑与局限

- **`git clone` 执行目录**：`runGit(ctx, dir, args)` 的 `dir` 是工作目录；clone 须在 `ManagedRepoBase`（父目录）执行、目标作为最后一个参数，不能在 target 内执行（target 尚不存在）。
- **异步 context 传播（关键坑）**：异步 goroutine **必须用 `context.Background()` 派生的新 context（带超时，如 30min）**，**禁用 `c.Request.Context()`**——HTTP 返回后 request context 会被取消，会导致 `git clone`/解压中途中断。token 仅在闭包内传递，不落 DB。
- **multipart 体积**：500MB 上传受 nginx/client 超时影响；超大仓库建议走"服务器目录"路径（先 scp 到 .28 再导入）。
- **导入后首次构建**：老项目可能无 ANP 部署所需的 Dockerfile → 首次"构建部署"可能失败。`buildpack` 检测可兜底，或在导入完成时提示用户补 Dockerfile。**不阻塞导入**。
- **异步中断**：MVP goroutine 在进程重启时丢失，Application 卡 `importing`。后续可持久化为任务表（参考 `codetask` 异步模式）+ 启动时恢复。
- **Next.js 16**：前端 breaking change，实现前必读 `node_modules/next/dist/docs/`。
- **保留 origin 的风险**：若上游强推（force push）后手动 pull 可能冲突；MVP 不自动同步，由用户自行处理。
- **凭证管理（后续）**：当前 token 一次性使用；后续若要支持"定期同步上游"需做加密凭证存储（vault/KMS），超出本任务范围。

# 阶段 3a：配额强制 PRD/设计

日期：2026-07-23
范围：4 维度强制 + 配额管理 API + 配额管理 UI + .28 部署验证

## 1. 背景

`project_quota` 表（迁移 000003）已建，但无任何代码查询它。项目能无限建应用 / 无限建库 / 无限调 AI。本阶段加 4 维度强制 + 管理 UI。

| 维度         | 列                           | 默认  | 拦截点                        |
| ------------ | ---------------------------- | ----- | ----------------------------- |
| 应用数       | max_apps                     | 20    | appdeploy.Create（建应用前）  |
| 库数         | max_databases                | 20    | pgsupply.Provision（建库前）  |
| 库总大小 MB  | max_total_db_mb              | 10240 | pgsupply.Provision（建库前）  |
| 每日 AI 调用 | max_capability_calls_per_day | 10000 | capability.Invoke（调 AI 前） |

### 2.1 Quota 模型

```go
type Quota struct {
    ProjectSpaceID           string
    MaxApps                  int // 默认 20
    MaxDatabases             int // 默认 20
    MaxTotalDBMb             int // 默认 10240
    MaxCapabilityCallsPerDay int // 默认 10000
    UpdatedAt                time.Time
}

// Usage 当前用量（limit+used 一起返回前端，渲染「X / Y」）
type Usage struct {
    Quota               Quota
    UsedApps            int
    UsedDatabases       int
    UsedDBSizeMb        int // 该项目所有库 SUM(pg_database_size) 折 MB（向上取整）
    UsedCapabilityToday int
}
```

### 2.2 错误

```go
type QuotaExceededError struct {
    Dimension string // apps / databases / capability_today / db_size
    Used      int
    Limit     int
    Unit      string // "" / "MB" / "次"
}
func (e *QuotaExceededError) Error() string {
    return fmt.Sprintf("配额超限[%s]：已用 %d%s / 上限 %d%s", e.Dimension, e.Used, e.Unit, e.Limit, e.Unit)
}
func IsQuotaExceeded(err error) bool
```

### 2.3 Store

- `GetOrCreate(ctx, psID) (*Quota, error)`：SELECT，sql.ErrNoRows 则 INSERT 默认值 returning（ON CONFLICT DO NOTHING 兜底并发）
- `Set(ctx, psID, q) error`：UPDATE（不存在报错；管理 UI 先 GetOrCreate）

### 2.4 Service（依赖 db + pgsupply.PGAdmin + pgsupply.InstanceReader）

4 个 check：

- `CheckApps(ctx, psID)`：`SELECT COUNT(*) FROM appdeploy_application WHERE project_space_id=$1` vs max_apps
- `CheckDatabases(ctx, psID)`：`SELECT COUNT(*) FROM appdeploy_database WHERE project_space_id=$1 AND status<>'deleted'` vs max_databases
- `CheckCapabilityToday(ctx, psID)`：`SELECT COUNT(*) FROM capability_usage WHERE project_space_id=$1 AND created_at::date=CURRENT_DATE` vs max_capability_calls_per_day
- `CheckDBSize(ctx, psID)`：取项目 PG 实例 admin_url → 连上查 `SELECT SUM(pg_database_size(db_name))` 该项目所有非 deleted 库 → 字节折 MB vs max_total_db_mb
  - 无实例/无库 → 0
  - 连不上 → 返回 nil（不阻塞建库；运维层告警）

`Usage(ctx, psID) (*Usage, error)`：聚合 4 维度当前用量 + 配额。

### 2.5 PGAdmin 扩展

原 `PGAdmin` 接口加 `DatabaseSizes(ctx, adminURL, dbNames []string) (map[string]int64, error)`。返回每库字节。`pgAdminClient` 实现：连 admin url，`SELECT datname, pg_database_size(datname)` WHERE datname = ANY($1)。

> 替代方案：连实例直接 `SELECT pg_database_size($1)` 单条。一次连查多个更高效。

### 2.6 依赖抽象（避免循环依赖）

- quota 不导入 appdeploy/pgsupply/capability 任何包（直接 SQL 查表）
- 通过接口注入：
  ```go
  type InstanceLookup interface {
      GetInstanceByProject(ctx, psID) (adminURL string, err error)
  }
  type PGSizeChecker interface {
      DatabaseSizes(ctx, adminURL string, dbNames []string) (map[string]int64, error)
  }
  ```
- pgsupply 提供 adapter 实现 InstanceLookup（薄包装 pgsupply.Store）

## 3. 接入点（4 处）

### 3.1 appdeploy.Create —— 拦应用数

`store.Create` 之前调 `quota.CheckApps`。超限 → 409 + 错误码 **40950** + 友好消息。

### 3.2 pgsupply.Provision —— 拦库数 + 库大小

`Provision` 最前（在 CreateAppDB 之前）调 `CheckDatabases` + `CheckDBSize`。
超限 → 返回 `*QuotaExceededError`，**不建任何记录**。
`appdeploy.Create` 收到该错误 → 把消息写到 `application.last_error`（不阻塞应用创建；前端应用列表显示警告）。

> 注：原代码 `_ = perr` 忽略所有 Provision 错误。改造：若是 QuotaExceededError，写到 last_error；其余仍忽略（原行为）。

### 3.3 capability.Invoke —— 拦 AI 调用

`Invoke` 在「鉴权 → 校验技能」之后、「调 agent-runtime」之前调 `CheckCapabilityToday`。
超限 → 429 + 错误码 **42950**（按 429 太频繁调用语义；前端可显示「今日调用已达上限 X」）。

### 3.4 库大小巡检 —— 暂不做

任务说放 3b。本阶段只拦建库时。

## 4. 配额管理 API

| 方法 | 路径                        | 权限     | 说明                                     |
| ---- | --------------------------- | -------- | ---------------------------------------- |
| GET  | `/project-spaces/:id/quota` | 任意成员 | 取配额 + 当前用量（GetOrCreate）         |
| PUT  | `/project-spaces/:id/quota` | admin    | 改 max_*（4 个字段都可选，未传保留原值） |

返回结构：`{quota: {...}, used: {apps, databases, db_size_mb, capability_today}}`。

PUT body：

```json
{
  "max_apps": 30,
  "max_databases": 30,
  "max_total_db_mb": 20480,
  "max_capability_calls_per_day": 20000
}
```

## 7. main.go 装配

```go
quotaStore := quota.NewStore(database)
```

## 10. 顾虑

- **多 PG 实例查询**：当前每项目一个 PG 实例（GetInstanceByProject），未来若多实例需改循环。本阶段按单实例实现，留 TODO。
- **Provision 配额失败的用户感知**：写到 application.last_error 字段，前端应用列表/详情能显示「库供给失败：配额超限」。
- **库大小查询频率**：每次 GET quota 都连 PG 实例查 size，规模大时有开销。本阶段可接受（管理页非高频）；3b 可加缓存。
- **capability 计数性能**：capability_usage 表加索引（project_space_id + created_at）已有，COUNT(*) 当日 N 条性能 OK。
- **配置默认值的演化**：若日后改默认值，已有 GetOrCreate 创建的行不变；新项目用新默认。可加 admin 批量调整工具（3b）。

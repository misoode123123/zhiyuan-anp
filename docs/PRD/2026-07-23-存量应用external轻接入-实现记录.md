  - Director 仍负责前缀剥离 + 身份头注入（X-User / X-Project-Space-Id / X-Trace-Id）

## 3. 关键设计决策

### 3.1 appgw 不 import appdeploy（保持单向依赖）

原架构：`appdeploy → appgw`（部署后写路由表）。若 gateway 要知道 deploy_mode 就得反查 appdeploy_application，破坏单向依赖。方案：**把 external_url 存到 appdeploy_route**（000010 加列），gateway 看 route.ExternalURL 决定反代方式，不需 join application。

### 3.2 external_url 路径前缀保留

external_url 可能形如 `http://h/erp/api`（域名 + 路径前缀）。反代时 `/apps/<app_id>/users` 应映射到 `/erp/api/users`（前缀 + rest），不是 `/users`。Director 把 `prefixPath`（external_url.Path trim 斜杠）拼到 rest 前。

### 3.3 UpsertRoute 清空 external_url

external→managed 切换（同一 app+env 二次部署）时，UpsertRoute（managed）显式 `external_url = ''`，否则 gateway 检测到 external_url 非空还走 external 分支。

### 3.4 external 应用 status=running

外部应用注册时即"运行中"（外部已活），不走 registered→building→running 状态机。Stats 直接探活 external_url。

### 3.5 鉴权头仍注入

external 应用大概率不认 X-User/X-Project-Space-Id；仍注入（应用可忽略）。route.auth_required 仍可强制平台登录（防外部直接访问）。

## 4. 顾虑与后续

- **接管需求（B ②）**：external 应用暂不与 requirement 关联（仅注册 + 入口 + 探活）。后续可加 `requirement.application_id` 指向 external 应用，让需求归属外部系统。
- **渐进纳入代码（B ③）**：external 应用想后续用 AI 编码迭代，需"转托管"——把 deploy_mode 切回 managed 并 EnsureRepo。可加专门的「转托管」入口（后续）。
- **HTTPS upstream**：NewSingleHostReverseProxy 支持 https target，但默认不验证证书（external 应用用自签证书时可用）；如需严格验证后续加 Transport。

# 阶段 3b：计量采集 PRD/设计

日期：2026-07-23
范围：appgw 应用 API 调用日志 + 库大小定时采集 + 库大小超限告警 + 原始 API
前置：[3a 配额强制](2026-07-23-配额强制3a-PRD.md)（4 维度拦截已落地）

## 1. 背景

3a 拦了超限，但「用量数据」两块缺失：

- **应用 API 调用**：appgw 只反代不记日志。每次 `/apps/<code>/...` 的调用（status / latency / caller）没留痕，看板（3c）无数据源。
- **库大小**：`GET /quota` 时连 PG 实例现算 `pg_database_size`，没存历史。已存在库涨满不会主动告警（3a 只在建库时拦）。

3b 补这两块 + 告警（log 级），为 3c 看板备数据。

## 3. appgw 记 access_log

### 3.1 model.go 加 AccessLog

```go
type AccessLog struct {
    ID, ProjectSpaceID, AppID, AppCode, Env, Caller, Method, Path string
    Status int
    LatencyMs int
    TraceID, CreatedAt string
}
```

### 3.2 store.go 加 LogAccess + ListAccessLogs

- `LogAccess(ctx, *AccessLog) error`：INSERT appgw_access_log（id = "al_"+uuid）
- `ListAccessLogs(ctx, appID string, limit int) ([]AccessLog, error)`：按 app_id 倒序，limit 默认 50

### 3.3 gateway.go 记日志

- Gateway 加字段 `accessLog AccessLogger`（接口：`LogAccess(ctx, *AccessLog) error`；*Store 实现；nil = 不记日志，向后兼容）
- `NewGateway(store, auth, logger, accessLog AccessLogger)`：最后参数可传 nil
- ReverseProxy 记日志策略：
  1. 进 handler 记 `start := time.Now()`
  2. `proxy.ModifyResponse`：拿 `resp.StatusCode`，算 `latency_ms = time.Since(start)`，调 `recordAccess` 异步写日志
  3. `proxy.ErrorHandler`（upstream 不可达 → 502）：同样记一笔（status=502）
  4. `recordAccess`：构建 AccessLog，`go func(){ _ = store.LogAccess(...) }()`（异步、失败 zap.Warn 不阻塞请求）
- caller 提取：鉴权通过 → user；否则 `X-Api-Key` header → `"apikey:" + <前 8 字符>`；否则 `"anonymous"`

> 记日志失败不能阻塞请求 —— 这是计量，不是业务。异步 goroutine + ignore error。

## 4. 库大小定时采集

### 4.1 pgsupply 加 Collector

新文件 `internal/pgsupply/collector.go`：

```go
type Collector struct {
    store      *Store
    pg         PGAdmin
    quotaStore QuotaReader // 读 project_quota.max_total_db_mb
    logger     *zap.Logger
}

type QuotaReader interface {
    MaxTotalDBMb(ctx, psID string) (int, error) // 不存在 → 默认值
}

func (c *Collector) CollectDBSizes(ctx context.Context) CollectResult
```

`CollectDBSizes` 流程：

1. `ListInstances(ctx)` 取所有 PG 实例（active）
2. 每实例：取 `admin_url_ref` + 该实例下所有 `appdeploy_database`（status<>'deleted'）的 `db_name` 列表
3. `pg.DatabaseSizes(ctx, adminURL, dbNames)` 一次连查多库字节
4. UPDATE `appdeploy_database.size_bytes`（逐行 UpdateAppDBSize）
5. **告警**：按 project_space_id 聚合 SUM(size_bytes) vs project_quota.max_total_db_mb，超限 `logger.Warn`（带 ps_id / used_mb / limit_mb）

返回 `CollectResult{Total, Updated, Failed, Alerts []AlertInfo}`。

### 4.2 store.go 加 UpdateAppDBSize + 辅助

- `UpdateAppDBSize(ctx, id string, sizeBytes int64) error`
- `ListAppDBsByInstance(ctx, instanceID string) ([]AppDatabase, error)`（按 pg_instance_id 过滤）

### 4.3 main.go 装配 + ticker

```go
collector := pgsupply.NewCollector(pgsupplyStore, pgAdmin, quota.NewQuotaReader(quotaStore), logger)
go runDBSizeTicker(ctx, logger, collector)
```

`runDBSizeTicker`：

- env `DBSIZE_INTERVAL_HOURS`（默认 1，0=关闭，非法回落默认）
- 间隔 `time.Duration(hours) * time.Hour`
- **进程启动后先跑一次**（不等 tick；首次部署立即采到当前 size），再 ticker 循环

## 10. 顾虑

- **access_log 写入压力**：每次 /apps/ 调用都写一笔，高 QPS 时 INSERT 压力。本阶段异步 goroutine 写，不阻塞请求；后续可批量 / 采样（3c 看板前评估）。
- **access_log 表膨胀**：没自动清理。后续加 TTL（保留 30 天）或归档到 OLAP。
- **CollectDBSizes 多实例**：按 pg_instance 逐个连查；当前每项目 1 实例，未来多实例天然支持（每实例独立查）。
- **告警只 log**：本阶段 zap.Warn，运维盯日志。3c/3d 可加告警表 + 通知（钉钉/邮件）。
- **size_bytes 采集精度**：定时采（默认 1h），两次之间有延迟；不实时（够看板用）。
- **ModifyResponse 与 ErrorHandler 都要记**：ModifyResponse 捕获 upstream 正常响应（含 4xx/5xx），ErrorHandler 捕获反代失败（502）。两路径互斥（ReverseProxy 失败走 ErrorHandler 不调 ModifyResponse）。

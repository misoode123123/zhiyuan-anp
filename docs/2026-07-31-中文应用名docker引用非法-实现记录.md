# appdeploy bug 修复:中文应用名导致 docker 镜像 tag/容器名非法

| 日期   | 2026-07-31                                                                    |
| ------ | ----------------------------------------------------------------------------- |
| 类型   | bug 修复（构建部署失败）                                                      |
| 现象   | 应用「客服机器人」(web/managed)构建部署失败，status=failed，exit 125          |
| 影响面 | 任何应用名含非 ASCII 字符（中文/emoji/特殊符号）的 web/service 应用都无法构建 |

## 1. 现象与根因

客服机器人在 .28 上点「部署」失败。查生产库 `appdeploy_instance.build_log`，真实报错：

```
invalid argument "appdeploy/客服机器人-test:v4" for "-t, --tag" flag: invalid reference format
See 'docker build --help'.
```

`exit status 125` 是表象（docker 守护进程级错误码），**根因是 docker reference 非法**：
docker 镜像路径段正则为 `[a-z0-9]+(?:(?:[._]|__|[-]+)[a-z0-9]+)*`，**只允许 ASCII**。
`appdeploy/客服机器人-test:v4` 的路径段含中文「客服机器人」→ `invalid reference format` → `docker build` 直接 exit 125，连源码都没开始编译。

`a.Name`（应用名）被**直接**拼进了 4 处 docker 引用，全部遇中文名即炸：

| 位置                                   | 用途                                                 |
| -------------------------------------- | ---------------------------------------------------- |
| `deployer.go` `Build`                  | 镜像 tag `appdeploy/<name>-<env>:v<n>`（**报错点**） |
| `deployer.go` `Deploy`                 | 容器名 `appdeploy-<name>-<env>-v<n>`                 |
| `handler.go` `buildAndDeploy`          | `RemoveByPrefix` 清理前缀 `appdeploy-<name>-<env>-`  |
| `handler.go` `Delete` → `RemoveImages` | 删镜像 glob `appdeploy/<name>-*`                     |

> 对照：仓库目录 `ManagedRepoDir(name)` 早已把中文名转成 `-`（`客服机器人` → `/data/repos/-----`），所以建仓/源码生成阶段没炸，唯独 docker 引用漏了 sanitize。

## 2. 方案

与现有 `codews.sanitizeID`（manager.go:384）同思路（小写、保 `[a-z0-9]`、其余转 `-`），在 appdeploy 包加 `dockerSlug(name)`：

- 小写化，`[a-z0-9]` 保留，其余 rune（中文/空格/符号）替换为 `-`，折叠连续 `-` 并去首尾；
- **纯非法字符**（如全中文「客服机器人」，替换后为空）退回 `app-` + 名字 sha256 前 12 hex —— 稳定可复现，同一应用每次得到相同 slug，`RemoveByPrefix`/`RemoveImages` 仍能匹配历史容器/镜像，不残留孤儿；且不同中文名哈希不同，避免容器名撞车。
- 兜底用哈希而非固定串（`sanitizeID` 用 "dev"）：两个纯中文应用不会撞同一个容器名。

4 处 `a.Name` → `dockerSlug(a.Name)` 统一替换（必须同函数，否则清理/删镜像匹配不上会留孤儿）。

> 取舍：`_`/`.`/大写在 docker tag 中本就合法（如 `ncc_deploy`），本方案统一转 `-`，仅对极少数含这些字符的存量应用（如 ncc_deploy → ncc-deploy）下次部署时遗留一个旧容器（`RemoveByPrefix` 是 best-effort，`usedPorts()` 会防端口冲突），不影响正确性，换取与 `sanitizeID` 一致的极简实现。

## 3. 改动

- `platform/backend/internal/appdeploy/deployer.go`
  - 加 `dockerSlug(name string)`（+ `dashRe`/`slugValidRe` 辅助），import `crypto/sha256`、`encoding/hex`。
  - `Build`/`Deploy` 两处 `a.Name` → `dockerSlug(a.Name)`。
- `platform/backend/internal/appdeploy/handler.go`
  - `buildAndDeploy` 的 `RemoveByPrefix` 前缀、`Delete` 的 `RemoveImages` 实参，`a.Name` → `dockerSlug(a.Name)`。
- `platform/backend/internal/appdeploy/deployer_test.go`
  - `TestDockerSlug`：ASCII 原样保留下划线/点/大写/空白的转换 + 中文 slug 合法/稳定/唯一。
  - `TestDockerSlug_ImageTagValidForChineseName`：回归「客服机器人」镜像路径段 + 容器名合法（修复前非法）。

## 4. 验证（.28 端到端）

| 项                                                   | 结果                                                                     |
| ---------------------------------------------------- | ------------------------------------------------------------------------ |
| `go build ./...`（platform/backend）                 | exit 0                                                                   |
| `go test -run TestDockerSlug… ./internal/appdeploy/` | ok                                                                       |
| scp 改动 → 重建 `deploy_backend_1`                   | 成功                                                                     |
| 重新触发客服机器人 test 部署                         | 15s 内 status=running                                                    |
| 镜像 tag                                             | `appdeploy/app-3b18080424ff-test:v5`（中文→sha256 slug，合法 reference） |
| 容器                                                 | `appdeploy-app-3b18080424ff-test-v5`，Up，9104→8080                      |
| 应用 URL `http://10.10.0.28:9104`                    | **HTTP 200**                                                             |
| `last_error`                                         | 空                                                                       |

slug `app-3b18080424ff` = `app-` + `sha256("客服机器人")` 前 12 hex，与 `dockerSlug` 实现一致；前 4 次失败在 tag 解析阶段，未产生任何镜像/容器，无孤儿需清理。

## 5. 经验

- 应用名 sanitize 要覆盖**所有**把它拼进外部标识（docker 引用、文件路径、git 分支…）的位点，逐一排查不能漏；本次仓库路径已处理、docker 引用漏了。
- `exit status 125` 这类笼统码要去 `build_log`/stderr 找原始信息（`invalid reference format`），不要在笼统码层面猜。

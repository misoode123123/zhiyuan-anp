## 1. 目标(待办 1)

子项目 A 让 `.31` Windows 节点改走 SSH 绕过 WinRM 401、`.30` docker_tcp 同时出 OS 指标 + 容器数。但前端 `/servers` 编辑表单的 SSH 凭证块只有 `ssh_user`/`ssh_key`,**缺 `ssh_password`** —— Windows SSH 节点(connect_type=ssh + 密码认证)只能靠 SQL 配,UI 配不了。

后端早已就绪:迁移 `000026_ssh_password`、`DeployNode.SSHPassword`、`SSHExecutor` 密码认证、`UpdateNode` 空值保留、`ListNodes` 掩码。**缺口纯在前端 UI**。

## 2. 改动

### 2.1 前端 `platform/frontend/app/servers/page.tsx`

- form state 加 `ssh_password: ""`(与 `ssh_key` 同组)。
- SSH 凭证块(`ct===ssh || docker_tcp`)加「SSH 密码」input:`type=password`,placeholder「编辑时留空不修改密码」,与 `winrm_password` 完全对称。
- 布局:`ssh_user`(1 col)+ `ssh_password`(1 col)+ `ssh_key`(span-2);CSS grid 把 span-2 的私钥自然推到下一行,与 WinRM 块视觉一致。
- 提交链路不变:`JSON.stringify(form)` 直传;`ssh_password` 留空时后端 `UpdateNode`(handler.go:2041-2052)保留旧值。

### 2.2 顺带修复:CreateNode 响应凭证掩码泄露

端到端验证时发现 `CreateNode`(handler.go:2003)`httpx.Created(c, n)` 直接返回节点对象,**未掩码** ssh_password/ssh_key/winrm_password —— POST 创建响应明文回密码。而 `UpdateNode`(2063-2066)、`ListNodes`(1993-1995)均已掩码,三处不一致。

修复:`CreateNode` 响应前补同样掩码,与 `ListNodes`/`UpdateNode` 对齐。(不影响 DB 落库:掩码的是响应内存对象,`nodeStore.Create` 已先写入真实值。)

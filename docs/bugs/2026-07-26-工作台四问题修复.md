## 3. 关键教训：guard name→id 回归（修 A 坏 B）

修复 membership（删错位行）后，**admin 派发编码变成 403**。根因：

- `guard.go:AutoRequire` 直接用**用户名** `"admin"` 查 `membership.user_id`，但 user_id 存的是 `usr_xxx`。
- 之前 admin 能派发，**靠的正是错位行**（`user_id=admin`）让 guard 的错误查询命中。
- 删错位行后，guard 的预存 bug 暴露 → 403。

git log 的 `e91851b fix(rbac): my-tasks name->id解析` 只修了 my-tasks，**漏了 guard**。本次补齐 guard 的 name→id 解析。

> **教训**：修数据正确性（membership user_id 标准化）前，必须检查所有依赖该字段的查询路径是否都按标准（usr_xxx）查询。错位数据可能反向"养活"了某个有 bug 的查询——修数据会暴露它。类似 [[sqlite-test-pg-type-trap]]：sqlite 单测掩盖 PG 类型问题，错位行掩盖 guard bug。

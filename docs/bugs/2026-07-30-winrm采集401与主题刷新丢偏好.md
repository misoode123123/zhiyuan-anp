## Bug 1：WinRM 采集

### 取证链(.28 生产实测)

- `.28` backend docker logs 反复:`collect node_9ca04ef9 failed: parseWindowsCombined: expect 5 fields, got 1 in ""`
- 节点 `node_9ca04ef9`(10.10.0.198, winrm, user=yxt),DB `winrm_password` 长度 0(空)。
- 加 DIAG 探针 `Write-Output probe-ok`:`probe stdout="" exit=1 err=dial tcp 10.10.0.198:5985: i/o timeout`(后变 401)。
- 原 monitor.go `combined, _, _, _ := exec.Run(...)` **把 err 丢了**,所以只看到「空输出」假象,真错误(网络/鉴权)被埋。

### 真根因(分层)

1. **代码层 A:err 被丢弃** —— `exec.Run` 返回的 dial/鉴权 err 被 `_` 丢,转成误导性 `parseWindowsCombined 空输出`。87c87e0 的「PowerShell 包装」是误诊:命令根本没到 PowerShell,卡在连接/鉴权。
2. **代码层 B:密码被 UpdateNode 清空** —— `ListNodes`/`UpdateNode` 返回时把 `winrm_password` 掩码成空串(handler.go),前端编辑保存回传空串,`NodeStore.Update` 无条件写空 → 真密码被清空。
3. **代码层 C:winrm 客户端用 Basic auth** —— `winrm.DefaultParameters.TransportDecorator=nil` → 默认 `clientRequest.Post` 用 `req.SetBasicAuth`(HTTP Basic)。Windows WinRM 默认禁止 HTTP 上的 Basic → 服务器返 401,且 401 响应体是 text/html(非 `application/soap+xml`)→ `body()` 报 `invalid content type` → `401 - invalid content type`。
4. **服务器侧:.198 WinRM 鉴权拒绝**(非代码) —— `Microsoft-HTTPAPI/2.0`,`WWW-Authenticate: Negotiate` only。curl `--ntlm -u yxt:Xywj.123` POST /wsman 返 401(正确密码 & 错误密码都 401,各种用户名前缀都 401)。Go ClientNTLM 行为与 curl --ntlm 一致(都 401),代码 NTLM 已对,剩下是 .198 服务器端拒绝 NTLM/Negotiate 鉴权。

### 代码修复(已 .28 验证)

- `monitor.go` windows 分支:捕获 `runErr` 并透传(`return fmt.Errorf("winrm 采集 %s: %w", n.ID, runErr)`),degraded 日志显示真因(如 `401`)而非「空输出」。
- `handler.go UpdateNode`:收到空 `winrm_password`/`ssh_key` 时保留 DB 旧值(凭证保留),不再被掩码空串覆盖。
- `remote_executor.go WinRMExecutor.Run`:`params.TransportDecorator = func() Transporter { return &ClientNTLM{} }`,用 NTLMv2(等同 curl --ntlm)替代 Basic。Basic 在 Windows WinRM 必 401。
- 单测:`TestUpdateNode_PreserveEmptyPassword` 空密码回传保留旧值;`parseWindowsCombined` 已有测试。

### 服务器侧待办(在 .198 本机以管理员跑)

curl --ntlm 正确密码仍 401,说明 .198 的 WinRM 鉴权/账号被服务器侧拒。需在 .198 本机(RDP/控制台管理员)排查:

```powershell
# 1) WinRM 基础配置(若未启用)
winrm quickconfig -q

# 2) 允许 HTTP 明文(5985)。默认新版 Windows AllowUnencrypted=false 会拒 HTTP
winrm set winrm/config/service '@{AllowUnencrypted="true"}'
winrm set winrm/config/client '@{AllowUnencrypted="true"}'

# 3) 放开 Negotiate/NTLM 鉴权(服务器只回了 Negotiate,可能 NTLM 被关)
winrm set winrm/config/service/auth '@{Negotiate="true";NTLM="true"}'

# 4) 本地账号网络登录:UAC 默认拦本地账号 WinRM,设 LocalAccountTokenFilterPolicy
Set-ItemProperty -Path HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System -Name LocalAccountTokenFilterPolicy -Value 1 -Type DWord

# 5) 防火墙放行 5985(TrustedHosts 也加 .28 来源)
netsh advfirewall firewall add rule name="WinRM-HTTP-In" dir=in protocol=TCP localport=5985 action=allow
Set-Item WSMan:\localhost\Client\TrustedHosts -Value "*" -Force   # 测试用,生产收敛到 .28 IP

# 6) 确认 yxt 是管理员或 Remote Management Users 组成员;确认密码无误(注意大小写)
```

验收:.28 backend 日志不再 `401`,改采到 cpu/mem/disk;或 `docker exec deploy_backend_1 curl --ntlm -u yxt:<pw> -X POST -d x http://10.10.0.198:5985/wsman` 返 200。

## Bug 2：主题刷新丢偏好

### 取证链(.28 生产实测)

- curl 首页 HTML 的 inline 主题脚本:`localStorage.getItem(undefined)` —— `THEME_STORAGE_KEY` 在 server 侧变成 `undefined`!
- 切换 dark:客户端 `theme.tsx`(`"use client"`)里 `THEME_STORAGE_KEY="anp.theme"` 正常 → 写 `localStorage["anp.theme"]="dark"`。
- 刷新:inline 脚本 `getItem(undefined)`→ 查 key `"undefined"`→ null → 回退系统偏好 → dark 偏好丢失。

### 真根因

`layout.tsx`(server component)从 `"use client"` 模块 `lib/theme.tsx` 导入 `THEME_STORAGE_KEY`。**App Router 的 client/server 边界只透出「组件」绑定,非组件的 const 跨边界导入到 server 侧拿到 `undefined`**。故 `JSON.stringify(undefined)` → 模板插值 `undefined` → 脚本 `getItem(undefined)`。键名读写不一致(write "anp.theme"、read "undefined")→ 持久化失效。

87c87e0 把脚本从 head 移 body、mount 同步 state —— 都没碰到这个键名不匹配根因。

### 代码修复(已 .28 验证)

- 新增纯模块 `lib/theme-constants.ts`(无 `"use client"`),导出 `THEME_STORAGE_KEY` + 纯函数 `buildThemeInlineScript()`。server 与 client 都能直接求值拿真值。
- `theme.tsx`:从 `./theme-constants` 导入 `THEME_STORAGE_KEY`(re-export)。
- `layout.tsx`:用 `buildThemeInlineScript()`,不再从 client 模块导入 const。
- 单测:`buildThemeInlineScript` 脚本含 `localStorage.getItem("anp.theme")`、不含 `getItem(undefined)`、含 `classList.toggle('dark',d)`。
- .28 验证:curl 首页 inline 脚本现 `localStorage.getItem("anp.theme")`(原 `getItem(undefined)`)。

## 经验

- 「err 被 `_` 丢」会把网络/鉴权层错误转成解析层假象,系统性误导。生产采集失败先看 err 别吞。
- App Router:server component 别从 `"use client"` 模块导入非组件 const,会拿 undefined。常量放纯模块。
- Windows WinRM 默认禁 HTTP Basic,Go winrm 客户端必须显式设 NTLM transport(`ClientNTLM`),否则必 401。

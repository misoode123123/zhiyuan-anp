# 应用构建卡在"构建中"停不下来 — 实现记录

- 日期：2026-07-28
- 影响范围：应用部署（appdeploy）构建链路；现象集中在导入应用 `ncc_deploy`(app_40d9e38f)
- 触发场景：opencode 编码界面点击"构建部署(test)"，编码界面报错，应用部署页一直"构建中"

## 1. 现象

- 编码工作台点"构建部署(test)"后，编码界面无 running/failed 反馈；
- 应用部署页(`applications`)对该应用持续显示"构建部署中…"，进度条永不消失；
- .28 后端无构建错误日志、无 panic；DB 中 `appdeploy_application.status` 与 `appdeploy_instance.status` 均卡 `building`，`build_log` 为空，无运行容器。

## 2. 根因（三层叠加）

### 2.1 触发层：导入应用自带 Dockerfile 指向本地缺失镜像

- `ncc_deploy` 由"导入已有项目"上传，自带 Dockerfile `FROM node:18-alpine`；
- .28 本地仅有 `node:20-alpine`，缺 `node:18-alpine` → `docker build` 触发 pull。
- 注：buildpack 自动生成的 Dockerfile(buildpack.go)全部命中本地镜像(node:20-alpine/golang:1.25-alpine/python:3-alpine/nginx:alpine)，**无此问题**；仅导入应用自带 Dockerfile 不可控。

### 2.2 环境层：.28 "半内网"+ mirror 配置混乱致 pull 极慢

- `/etc/docker/daemon.json` 配了 14 个公网 mirror（阿里/腾讯/华为/网易/百度/SJTU/USTC…），含占位符 `https://your_preferred_mirror` 与重复项，多数源已失效；
- docker 逐个尝试 mirror、每个超时才换下一个 → pull 一个 `node:18-alpine` 可达数分钟；
- dockerd 日志大量 `failed to query DNS server: 8.8.8.8:53 ... i/o timeout`（间歇性，非永久不通）。
- 结论：非"拉不到"，是"慢"。

### 2.3 代码层（根本，决定一次慢就永久卡死）

| #   | 位置                                 | 缺陷                                                                                                                    | 后果                                                                    |
| --- | ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| C1  | `deployer.go:45` `runDockerOn`       | `docker build/run` 用调用方传入的 ctx，而 `buildAndDeploy` 传 `context.Background()`(handler.go:1360)**无超时**         | build 卡住时 `cmd.Run()` 永久阻塞，goroutine 挂起                       |
| C2  | `handler.go:1359` `buildAndDeploy`   | goroutine **无 `defer recover()`**                                                                                      | 任一步 panic 状态永卡 building（对照 `dev/coding.go:92-99` 有 recover） |
| C3  | `handler.go:1362-1364` / `1372-1375` | `store.Get` / `GetOrCreateInstance` 失败时 early-return，**不 markFailed**                                              | DB 抖动即卡 building                                                    |
| C4  | `workspace-frame.tsx:193`            | 轮询读 `d?.application?.instances`（`Application.Instances` 是 `db:"-"` 恒空）；顶层 `d.instances` 才有值(detail.go:88) | 编码界面永远收不到实例态，running/failed 都不触发                       |
| C5  | `workspace-frame.tsx:203`            | 轮询 `n>40` 超时只 `clearInterval`，**不 setDeployState("failed")**                                                     | 超时后按钮仍"构建中…"                                                   |

> 反向印证：止血时 `kill` 卡死的 build 进程后，阻塞的 `cmd.Run()` 立即返回(`signal: terminated`)，代码正常的 `Build 失败→markFailed` 随即生效，状态正确翻 `failed`。**证明只要 build 能被终止，闭环就正常**——C1(无超时)是核心。

## 3. 运行时证据（.28）

- 卡死进程：`docker build -t appdeploy/ncc_deploy-test:v2 /data/repos/ncc_deploy`，ELAPSED 17m+，CPU `00:00:00`，State `S(sleeping)`，无子进程；
- docker images 无 `ncc_deploy` 镜像 = 从未成功；
- DB：`application`/`instance`(test) 均 `building`、`build_log=NULL`、`deploy_node_id=NULL`；
- 前端高频轮询：`app_40d9e38f` 的 `/stats` 6918 次、`/detail` 4497 次（应用列表页 + 部署页双轮询）。

## 4. 修复方案

### 4.1 后端（根本）

- **F1（核心）docker 命令加超时**：`buildAndDeploy` 内为 Build 阶段与 Deploy 阶段分别用 `context.WithTimeout(ctx, N)` 包裹（Build 含 pull，给足上限如 10min；Deploy 如 3min）。超时 ctx cancel → `exec.CommandContext` 杀子进程 → `cmd.Run()` 返回 ctx err → 走 markFailed。
- **F2 goroutine recover**：`buildAndDeploy` 顶部 `defer func(){ if r:=recover();r!=nil { markFailed(...) } }()`，参照 `dev/coding.go:92-99`。
- **F3 early-return 兜底**：`handler.go:1362`、`1372` 两处 return 前先 `markFailed`。
- （可选 F4）`applications` 页 building 态加客户端超时兜底，不完全依赖后端。

### 4.2 前端

- **F5** `workspace-frame.tsx:193` 改读 `d?.instances?.find(i=>i.env==="test")`（顶层）。`last_error`(line 199) 读 `d?.application?.last_error` 保持不变。
- **F6** `workspace-frame.tsx:203` 超时分支补 `setDeployState("failed")` + `setDeployErr("构建超时，请查看构建日志")`。

### 4.3 环境（止血 + 加固）

- **E1** 预置常用基础镜像（node:18/20-alpine、python:3-alpine、golang、nginx、alpine:3.19）到 .28 本地，使常见 FROM 命中本地不 pull；
- **E2（择机，需重启 dockerd 影响线上）** 清理 `daemon.json` mirror 列表：删占位符/重复项，保留 2-3 个稳定源；
- **E3（架构级，后续）** 内网架 harbor，buildpack/导入 Dockerfile FROM 指内网 IP，彻底摆脱公网 DNS。

## 5. 验证（.28 端到端）

1. scp 后端 + 前端产物到 .28，docker-compose 重建 backend/frontend；
2. 对 `ncc_deploy`(自带 FROM node:18-alpine) 重新 deploy：
   - 镜像本地已预置 → 走 running；
   - 故意改 FROM 为不存在的镜像 → 应在超时上限内翻 `failed`、`build_log`/`last_error` 有内容、前端停止"构建中"；
3. 编码界面 deploy 轮询：成功显示 running+URL，失败显示 failed+原因，超时不再卡"构建中…"。

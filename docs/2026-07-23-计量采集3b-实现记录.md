**ReverseProxy 记日志策略**（关键）：

- `proxy.ModifyResponse`：捕获 upstream 正常响应（含 4xx/5xx），拿 `resp.StatusCode`
- `proxy.ErrorHandler`：捕获反代失败（upstream 不可达 → 502）—— 与 ModifyResponse 互斥
- `recordAccess` 用 `go func{}` 异步写 + 独立 5s ctx（不复用 request ctx，避免请求结束后 ctx 被 cancel）
- 记失败 `zap.Warn`，**不阻塞请求**（计量不影响业务）
- caller 推断：鉴权 user → `X-Api-Key` 前 8 字符 → "anonymous"
- 鉴权 401 在 recordAccess 之前 short-circuit，**不计**（未通过身份核验不算「应用访问」）

### db size 定时采集 + 告警（`pgsupply/collector.go`）

| 文件                               | 改动                                                                                                                                                                                         |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pgsupply/model.go`                | `AppDatabase` 加 `SizeBytes int64` 字段（自动序列化）                                                                                                                                        |
| `pgsupply/store.go`                | `appDBCols` 加 size_bytes；`ListAppDBsByInstance` / `UpdateAppDBSize` / `ListActiveInstances` / `ProjectTotalSizeMb` / `MaxTotalDBMb`（直接查 `project_quota`，不导入 quota 包避免循环依赖） |
| `pgsupply/collector.go`（新）      | `Collector.CollectDBSizes`：遍历 active 实例 → 每实例 `DatabaseSizes` 一次连查 → UPDATE size_bytes → 按项目聚合判超限 → zap.Warn                                                             |
| `pgsupply/collector_test.go`（新） | fake PGAdmin：基本采集 / 告警 / 实例连不上 / store 访问器                                                                                                                                    |
| `pgsupply/store_test.go`           | Truncate 加 `project_quota`（隔离）                                                                                                                                                          |

`CollectDBSizes` 流程：

1. `ListActiveInstances` 取所有 active 实例
2. 每实例 `ListAppDBsByInstance` + 提取 `dbNames` → `pg.DatabaseSizes(adminURL, dbNames)` 一次连查
3. 逐库 `UpdateAppDBSize(ad.ID, sizes[ad.DBName])`；库在 PG 中找不到 → 记 0 + warn
4. 按 `psBytes[psID]` 累计 → `MaxTotalDBMb(psID)` 比对 → 超 → zap.Warn + `AlertInfo`
5. 单实例失败不中断（continue 下一实例）

### main.go 装配

```go
dbSizeCollector := pgsupply.NewCollector(pgsupplyStore, pgAdmin, logger)
```

- env `DBSIZE_INTERVAL_HOURS`（默认 1，0=关，非法回落默认）

- 之后定时循环

## 顾虑 / 后续

- **access_log 写入压力**：每次 `/apps/` 调用异步写一笔 INSERT；高 QPS 时 DB 写压力。本阶段异步 goroutine 不阻塞请求；规模上来后可批量写 / 采样 / 移 OLAP。
- **access_log 表膨胀**：当前无 TTL。建议加定时清理（保留 30 天）或归档到看板库（3c 前评估）。
- **size_bytes 采集精度**：默认 1h 采一次，两次之间数据有延迟。看板场景够用；需实时仍走 3a 的 `GET /quota`（连实例现算）。
- **告警只 zap.Warn**：本阶段运维盯日志。3c/3d 可加告警表 + 钉钉/邮件通知。
- **401 不计 access_log**：鉴权失败 short-circuit 在 recordAccess 之前。若需统计「被拒访问」（安全审计），3c 可单独记 `auth_fail_log`。
- **多实例支持**：CollectDBSizes 按 pg_instance 逐个查，天然支持每项目多实例（当前每项目 1 个）。

# 编码工作台（codews / opencode）多用户隔离与安全 · 分阶段方案

- 日期：2026-08-09
- 背景：用户反馈"着急上线，目标先跑通，安全后期加强"。本文据此把工作切成**期1 上线跑通（现在）**与**期2 安全加强（上线后）**两档。
- 依据：两路只读核查（HTTP→鉴权→Ensure 隔离链路；opencode 子进程共享态/进程/网络/key/git），所有结论附 `file:line`，末尾「证据清单」汇总。

---

## 一、现状结论（事实）

### 1. 隔离设计基本正确——五个维度，正常用户名下互不踩踏

每 `(app, user)` 组合独立（不同登录用户 → 不同开发者身份）：

| 维度 | 代码 | 结论 |
|------|------|------|
| git worktree 目录 | `codews/manager.go:556` `repoDir/.worktrees/<sanitize(userID)>` | 不同 |
| git 分支 | `codews/manager.go:565` `dev-<sanitize(userID)>` | 不同 |
| opencode 进程 + 端口 | `manager.go:237` `allocPortLocked()`（9400–9450 池） | 不同进程 + 不同端口 |
| 会话 key（进程注册表） | `manager.go:218` `appID + ":" + userID`（**原始用户名**） | 不同 |
| per-user 模型配置 | `manager.go:167` `xdgConfigDir(base, appID, userID)` | 不同目录 |

链路无断点：HTTP 入口 `appdeploy/handler.go:153` `/workspace` → JWT 中间件 `auth/middleware.go:51` 取用户名 → `handler.go:285,289` 透传 `Ensure`。`/inject-requirement`、`/git-status`、`/commit`、`/submit`、`/merge`、`/deploy` 等均独立从 `c.GetString(auth.CtxUserID)` 取同一口径，无写死/顶替。

> **跑通判定**：对种子用户/常规纯字母数字用户名（如 `admin`、`yxt`、`zhangsan`），多人同开一个 app **功能上完全隔离、各自独立编码**，已具备上线条件。期1 的核心工作是**实测确认**这一结论，不是推倒重做。

### 2. 两个真实的功能性隐患（影响"跑通/数据完整性"）

**(A) sanitize 碰撞 —— 跨用户代码串改**（潜在，需触发条件）

`sanitizeID`（`manager.go:582-596`）把 `.`、`_`、空格、`@`、大写、中文等**一律→`-`**。故 `alice.bob`、`alice_bob`、`alice bob` 三个合法、DB 唯一、可登录的不同用户，sanitize 后**同为 `alice-bob`**（测试 `coverage_test.go:31-41` 已自证）。

碰撞后果：worktree 目录、分支、XDG 配置目录全部撞串；而会话 key（原始 name）仍分开 → **两个独立工作台 UI，背后却读写同一份代码/同一份 opencode.json**，B 能看到/提交/合并/部署 A 的代码，A 无感知。AGENTS.md 落盘路径 `handler.go:306` 同样命中。

- **触发条件**：存在 sanitize 后同串的用户名对。当前 `CreateUser`（`auth/handler.go:99-117`）对 name **零格式校验**，无任何护栏阻止这种用户名被建出来。
- **现状风险**：种子用户不受影响；但上线后若管理员用 `zhang.san` / `zhang_san` 建号即中招。

**(B) worktree 建失败静默回退主仓**（`manager.go:572-575`）

worktree 两步 `add` 都失败时兜底 `return repoDir` → opencode 以主仓根为 cwd 编码，**直接 commit 进主仓默认分支**，污染主线/他人分支。仅在 worktree add 异常路径触发，但失败是静默的（仅 log）。

### 3. 安全面盘点（均**不影响跑通**，全部归入期2）

| # | 项 | 现状（证据） | 性质 |
|---|----|------|------|
| S1 | 进程身份 | 容器 root，无降权；挂宿主 `docker.sock` + `/host/proc`（`Dockerfile-backend:11-23`、`docker-compose.prod.yml:39-40`） | 安全·高危 |
| S2 | 端口暴露 | opencode `--hostname 0.0.0.0`（`tool.go:27`），9400–9450 直映宿主（`compose:50-51`），web UI **无鉴权**；浏览器直连不经 nginx（`handler.go:308` 原样回传 url/port） | 安全·高危 |
| S3 | API key | per-user `opencode.json` 明文 `apiKey`、权限 **0644**（`opencode_gen.go:229`）；**且一份真 key 已提交入 git**：`platform/opencode.json:9` | 安全·既成泄露 |
| S4 | opencode.db | 全局共享单 sqlite（`manager.go:36` 注释刻意不拆），所有用户会话/凭据缓存同库，仅靠 directory 字段软隔 | 安全 |
| S5 | git 主仓 | 所有用户共享主仓、同 root 身份，无分支保护/写域；`.worktrees/` 未 gitignore | 安全 |
| S6 | 并发 | 端口池 51（9400–9450）、全局、无排队/空闲驱逐，第 52 个 `(app,user)` → HTTP 500（`manager.go:603-611`） | 容量 |

## 二、期1 · 上线跑通（现在，目标：多用户各自独立可用）

> 原则：不引入任何"为安全而重架构"的改动。隔离主体已成立，期1 = **实测确认 + 两个低成本防坑小修 + 风险登记**。

### 1.1 【核心】多用户隔离实测验证（.28）
代码层已证明隔离成立，需运行时确认：以两个不同账号（如 `admin` + 另一个真实账号）同开同一 app，核对：
- 各自 worktree 目录、`dev-<user>` 分支独立；
- 各自独立 opencode 进程 PID、独立端口；
- A 的会话内容 B 看不到，A 的改动不进 B 的工作区。
产出：验证记录（截图/命令输出）贴入本文。

### 1.2 端口容量确认
确认上线当天同时在线编码的开发者数 N ≤ 51（端口池上限）。若 N 可能超限，扩 `portMax`（`manager.go:31-32`，低成本改常量）即可临时缓解；正式排队/驱逐机制留期2。

### 1.3 【建议小修】worktree 建失败不再静默回退主仓
`manager.go:572-575`：兜底 `return repoDir` 改为 `return ""`（或返回 error），由调用方/`Ensure` 以明确错误中止，而非让 opencode 悄悄写主仓。改动 2 行，杜绝主仓被污染。

### 1.4 【建议小修】用户名格式校验，杜绝碰撞隐患
`auth/handler.go` 的 `CreateUser` 加 name 格式约束（仅 `[a-z0-9-]+`，或至少禁止 `.`、`_`、空格三者共存）。一处校验即可从源头封死 1.A 的碰撞类，零侵入隔离逻辑。已有碰撞型用户名需手动整改。

> 注：1.A 的**根治**（隔离键从"用户名"换成"DB 主键 `usr_xxx`"，sanitize 安全且天然唯一）会改动 `Ensure` 签名及 ~7 处 handler 调用 + SendPrompt + AGENTS.md 路径，属较大改动，归入**期2**（见 2.4）。1.4 是低成本保险，先把"跑通"挡住。

### 1.5 已知安全风险登记（上线即接受，期2 逐项收口）
明确记录 S1–S5 为"上线已知风险"，前提是**仅内网/VPN 可达 .28:9400–9450**。上线前必须确认：9400–9450 **未对公网开放**（这是当前唯一的事实安全底线）。

## 三、期2 · 安全加强（上线后，按优先级）

### 2.1 【P0】端口收回 + 反代鉴权（堵 S2，最直接的越权入口）
- opencode `--hostname` 改 `127.0.0.1`（`tool.go:27`），不再绑所有网卡；
- 取消 9400–9450 的宿主端口映射（`compose:50-51`），改由 nginx 或后端反代；
- 反代层强制平台 JWT/会话鉴权，按 `(app,user)` 只放行自己的工作台端口。
> 与已作废的"反向代理为渲染"（原任务 #35）区分：那次是为错误的"REST 不渲染"结论而做；此处反代的目的是**鉴权隔离**，理由成立、必要。

### 2.2 【P0】明文 key 轮换 + git 历史清理（堵 S3 既成泄露）
- 轮换 `platform/opencode.json:9` 那把已入 git 的真 key；
- 清理 git 历史（filter-repo）并通知相关方；
- per-user `opencode.json` 权限 `0644 → 0600`（`opencode_gen.go:126,229`）；
- 密钥扫描器（`security/scanner.go`）补 `apiKey`/明文规则，纳入 pre-commit/CI 拦截。

### 2.3 【P0】进程降权 + 去多余宿主挂载（堵 S1）
- 后端容器加非 root `USER`，opencode 子进程 per-user uid（`tool.go` 设 `SysProcAttr.Credential`）；
- 评估并尽量移除 `docker.sock`、`/host/proc` 挂载（`compose:39-40`），非必要不挂；
- 中期：每用户独立容器/沙箱，彻底隔离 blast radius。

### 2.4 【P1】隔离键改 DB 主键（根治 1.A）
将 worktree/分支/XDG/会话匹配的隔离键从 `CtxUserID`（用户名）统一改为 `CtxUserDBID`（`usr_xxx`，`middleware.go:52` 已在 context 里），彻底消除 sanitize 碰撞类。改动面：`Ensure` 签名 + 各 handler 取值 + `SendPrompt` + `RefreshAgentsMD` 路径（`handler.go:289,306` 等）。需配套迁移说明（旧 `.worktrees/<用户名>` 目录成为孤儿，首开重建）。

### 2.5 【P1】opencode.db per-user 拆分（堵 S4）
注入子进程时除 `XDG_CONFIG_HOME` 外再设 `XDG_DATA_HOME`（或 `HOME`）为 per-user 目录（`manager.go:173` `buildOpenCodeEnv`），让 transcript/凭据缓存不再跨用户同库。需评估每用户 sqlite 的磁盘成本（当前共享库已 1GB+）。

### 2.6 【P1】git 主仓权限控制（堵 S5）
- 主线 main 设 protected branch，禁直推；
- per-user 仅可写自己的 `dev-<user>` 分支；
- 主仓 `.gitignore` 加 `.worktrees/`；worktree 写域/锁约束。

### 2.7 【P2】并发治理
端口池满时排队/等待（而非直接 500）、空闲会话驱逐回收端口、`/workspace` 限流。
